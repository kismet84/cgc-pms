## 2. 范围、非目标与不变量

### 2.1 范围

1. 将 15 个 `XX-yyyyMMdd-XXX` 本地生成器迁移到现有 `CodeGenerationService`，统一 `001..999`、畸形历史号和耗尽失败语义。
2. 使对应 13 个唯一 Mapper 数据源按租户、日期前缀读取含软删除历史的最大合法编号；项目双入口和采购订单双入口共享既有 Mapper，不增加领域生成器。
3. `QualitySafetyService.nextIssueCode` 保留 `inspectionCode-ISS-XXX` 本地语义，只在第 1000 个候选号前失败关闭。
4. 在最终实现 SHA 的干净隔离快照复跑现有 9 组本地 Live E2E，并生成绑定 SHA 的摘要。
5. 长任务失败提示改为“修复后重跑全部 Completion Contract 检查”，用一项双检查回归固定行为。
6. GitHub `master` 分支保护在既有 14 项基础上增加 `desktop-launcher`，保持 `strict=true` 与 GitHub Actions App 绑定。
7. 同步计划索引、当前焦点、项目地图、唯一问题源和最终质量报告。

### 2.2 非目标

- 不扩展三位编号、不创建序列表、Redis 计数器、新 migration、新编号服务或第三套生成器。
- 不合并 `CodeGenerationService` 与 `BusinessCodeGenerator`；二者现有持久化、作用域和 28 个已统一调用方不变。
- 不修改 3 个已有保护的特殊实现：`CashJournalService`、`ProductionMeasurementService`、`ProjectFileService`。
- 不创建 `release-candidate.yml`、nightly、required Live CI、远端 fresh MySQL、生产或目标环境门禁。
- 不给长任务门禁增加 per-check checkpoint、缓存、Schema、状态或通知协议。
- 不增加 `build-summary` 聚合任务或故意制造失败 PR；分支保护使用 GitHub 原生 required context。
- 不重写第81、83条历史计划或质量报告；历史 SHA 的既有交付结论保持有效。

### 2.3 不变量

- 日型业务编号继续为固定三位 `001..999`；`1000`、零、非数字、非三位和错误前缀均失败关闭。
- 租户、日期前缀和现有业务作用域不变；软删除记录继续占号，不得因删除复用历史业务编号。
- 唯一键、事务、既有冲突重试和 offset 语义保留；并发结果只能是唯一合法三位编号或稳定业务异常。
- `includeDeleted=true` 必须由 `DeletedCodeSource` 提供含软删除查询；缺少能力时不得静默回退 active-only。
- 质量问题子序号作用域仍为同租户、同检查单；第 999 个可生成，第 1000 个候选号抛统一容量异常。
- Live 只连接 loopback 与专用 `cgc_pms_demo_v2`，先通过无副作用数据源证明，再登录和加载演示数据。
- Completion Contract 失败修复后从首项全量复验；只有 `TASK_PASSED/NOTIFYING` 通知恢复点不重跑业务检查。
- GitHub `master` 保护的 required contexts 必须与仓库 15 项清单精确一致，全部绑定 `app_id=15368` 且 `strict=true`。

## 3. 最小实施设计

### 3.2 日型业务编号单一出口

## 6. 风险、失败分类、金丝雀与恢复

### 6.1 唯一失败分类

| 分类 | 适用情形 | 处置 |
| --- | --- | --- |
| `tool_config` | GitHub context/app 绑定或本地工具配置错误 | 修配置后重跑同一门禁，不改业务代码 |
| `tool_invocation` | 命令、参数、工作目录或测试选择错误 | 修调用并保留失败证据 |
| `environment_prerequisite` | loopback MySQL、浏览器、Docker 或 reset marker 前置不足 | 恢复本地前置；禁止转成生产要求 |
| `ready_issue_config` | 审计要求 RC、远端数据库、生产或目标环境 | 标记 `NOT_APPLICABLE_LOCAL_ONLY` 并关闭 |
| `retrieval_gap` | 审计会话、GitHub API、run 或摘要无法读取 | 补取证据；不得推定通过 |
| `quality_or_security` | 四位编号、租户/软删串号、测试失败、Live 异常或保护集不一致 | 阻塞对应 G 门并修复根因 |
| `unknown` | 无法落入以上分类 | 保持失败，缩小复现后重新分类 |

### 6.2 金丝雀

- **编号：** 本地测试租户分别预置 998、999、软删除 999、历史 1000 和畸形值；先跑一个 Mapper，再扩到 13 个参数化实例。
- **Live：** 先运行现有安全负例与数据源只读证明，再加载演示数据和执行 9 组用例。
- **长任务：** 仅用临时双检查 fixture 验证全量复验计数，不触发真实通知。
- **分支保护：** 写前保存 14 项快照，只增加 1 项并立即回读；下一张正常 PR 验证真实 `desktop-launcher` 必需状态。

### 6.3 回滚与恢复

- 编号整改异常时反向恢复第85条任务自有服务、Mapper、公共服务和测试补丁；无 migration，无 schema 回滚。测试数据按明确前缀清理，不动非任务数据。
- Live 失败时停止临时进程、保留脱敏摘要并恢复既有本地入口；不以关闭用例、改 required CI 或连接非本地环境规避。
- 长任务文案/测试回滚不改变既有状态机；若全量复验本身暴露缺陷，保持门禁失败并修根因。
- GitHub 配置异常时只通过 `/protection/required_status_checks` 子资源恢复原 14 项，其他 protection 配置不得写入；立即保持“禁止新 PR 转 Ready 或合并”，不得通过删掉 `desktop-launcher` 后宣称完成。
- Git 交付若未授权或任一 CI 失败，保留本地任务分支和证据，不 push、不合并、不删除分支。
