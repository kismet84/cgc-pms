# 第53条主线 M5 供应链与物资任务计划书

**Goal:** 在 M4 已正式收口基础上，将供应链与物资域 10 条 Legacy 路由迁移为可验收的 Clean-room V2 闭环，保持供应商招采、采购申请、订单、验收、仓储、库存流水、调拨和领退料的数量、价值、来源及状态均以服务端事实为准。 **Architecture:** 复用现有 V2 公共壳、请求层、权限守卫、Legacy API 契约和既有后端闭环；按“契约与只读金丝雀 → 供应商招采 → 采购申请/订单/验收 → 仓储库存 → 领退料 → 全量收口”串行推进；禁止新增平行库存账、通用手工出入库、前端权威数量计算或预测平台。

- 不连接生产数据库，不执行生产写入、commit、push、PR 或发布。

## 6. 权威事实矩阵

| 事实 | 权威来源 | V2 职责 | 必测 |
| --- | --- | --- | --- |
| 库存现存量/可用量/安全量 | 库存服务 | 字符串展示、提交业务输入、写后回读 | 空库存、负数拒绝、并发消耗 |
| 库存价值 | 服务端库存/交易事实 | 只展示，不本地累计 | 入出库前后对账 |
| 来源流水 | 服务端 transaction ledger | 只读追溯 | 验收、调拨、领料、退料来源 |
| 采购在途 | 已审批订单未收货余量 | 只读提示 | 部分验收、全部验收、重复读取 |
| 调拨 | 服务端事务与幂等键 | 提交一次、失败可重试、结果回读 | 重放、并发、安全库存、失败回滚 |
| 领退料状态 | 服务端领料/工作流/库存事务 | 按动作权限触发，不本地推进 | 驳回、重提、出库、退料 |
| 供应商招采状态 | 供应商招采服务 | 展示和授权动作 | 发布、报价、评审、定标、黑名单 |

数量、金额、ID 使用稳定字符串；空值与 `0` 区分。前端不得在成功响应前修改权威库存、在途或流水。

## 10. 停止条件

出现任一项立即停止当前切片，结论不得为通过：

- 库存数量、价值、来源流水或采购在途无法与服务端对账。
- 需要前端乐观写权威库存，或需要恢复通用手工出入库。
- 权限、租户/项目范围、状态或幂等语义需要猜测。
- 并发调拨、部分验收、重复出库或退料不能证明原子性与守恒。
- 为迁移页面必须新建平行账本、重构核心领域或连接生产环境。
- 同 SHA 验证缺失、测试顺序不稳定或 V2 门禁失败。
