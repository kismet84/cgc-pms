## 3. 核心不变量与目标契约

### 3.1 运行与备份不变量

1. 容器 1G 上限下，Java 最大堆不得等于容器上限；元空间、线程栈、直接内存、代码缓存和原生库必须有明确余量。
2. `mem_limit` 与 `deploy.resources.limits.memory` 必须一致；本地 `docker inspect` 的实际 cgroup 值是运行证据，YAML 文本不是。
3. heap dump 写入专用持久目录，权限最小化；不得落在容器临时层或进入 Git。
4. 备份只允许 `PARTIAL → VERIFIED → COMPLETE` 单向状态；消费端、保留任务和恢复脚本只能看到 `COMPLETE` 批次。
5. 同一批次必须包含 MySQL、MinIO 清单、统一 batch ID、时间、源库/桶、SHA-256、工具版本、结果和 manifest；任一成员失败，整批不可发布。
6. 备份 runner 不挂 Docker socket，不把密码写入命令日志、manifest 或仓库；失败返回非零并保留脱敏诊断。
7. 故障注入、恢复和清理只使用任务创建的临时目录、隔离 MySQL 数据库和隔离 MinIO bucket；不得操作当前开发数据。

### 3.2 安全与业务不变量

1. 租户 0 与非零租户的用户角色、角色菜单读写必须隔离；缺租户上下文、错误租户、跨租户 ID 均失败关闭。
2. 只有经过逐调用方证明的共享模板、系统初始化或显式管理路径可使用 `@InterceptorIgnore`；SQL 自身仍需包含必要租户条件，禁止 ThreadLocal 临时绕过。
3. 认证继续使用 HttpOnly access/refresh Cookie、SameSite=Strict 与双提交 CSRF。支持的是“同站、可跨端口/源”的本地模型，不承诺跨站 Cookie 认证。
4. 合法 `X-XSRF-TOKEN` 预检通过；未知 origin、`*`、缺/错 CSRF、Bearer 外部路径及凭据跨站请求继续拒绝。
5. 竣工 summary 的状态、门禁数量和金额必须由服务端权威事实计算；分页/懒加载不得漏项、重复、越权或把前端汇总变成第二事实源。

### 3.3 验证与证据不变量

1. contract CI、本地 live、MySQL 专项、浏览器 DOM 和 Compose 运行证据分别记录，互不替代。
2. JaCoCo 全局 instruction 0.73 / branch 0.60 是最低防回退线；高风险包和新增代码阈值只能基于 G0 当前报告单调提高。
3. 周期重扫必须可手动复跑、权限只读、Action 固定完整 SHA、构建镜像固定 digest，结果绑定 commit SHA。
4. Codemap 必须区分源码快照提交、包含范围脏状态、仅排除/自引用变化和 stale 模块；`--verify` 对包含范围漂移失败关闭。
5. 任何阶段证据必须绑定稳定分支/工作树、精确 HEAD、命令和实际结果；历史审查或旧 worktree 结果只作线索。

## 7. 风险、失败分类、金丝雀与恢复

### 7.1 主要风险

- 租户拦截变更影响认证、授权装配和系统初始化，可能造成跨租户泄露或合法用户失权。
- 备份脚本错误可能制造伪完整制品、误删保留批次或恢复到错误数据源。
- JVM 过度压缩堆会把 OOMKill 改成 Java OOM 或吞吐退化；只改 YAML 无法证明限制生效。
- 竣工接口拆分可能改变金额/状态语义、排序或页面首屏行为。
- MySQL 测试扩张和覆盖率抬线可能显著拉长 CI 或诱发通过排除绕过。
- 当前本地/跟踪分支分叉及并行 worktree 可能导致同文件成果丢失或重复集成。

### 7.2 失败分类

| 分类 | 示例 | 动作 |
