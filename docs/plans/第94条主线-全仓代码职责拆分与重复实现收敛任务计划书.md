### 1.3 拆分、合并和保留原则

1. 按路由、业务状态机、事务边界和变更频率拆；不按固定行数切片。
2. 先保留原 façade、barrel、URL 和公开方法，再迁移内部实现；调用方稳定后才删除兼容层。
3. 只合并语义和失败行为完全相同的代码；同名但粒度不同的 DTO、金额字段和状态不得合并。
4. 优先删除透明包装、重复映射和无行为 helper；不得为“统一风格”新增工厂、基类或通用框架。
5. 查询、组装、纯算法先拆；权限、金额、库存、文件副作用和写状态机最后拆，并保持原事务和锁序。
6. 每个批次必须能独立回滚，禁止跨批次同时修改同一个 SFC、Service、Mapper、契约文件或测试夹具。

## 3. 目标架构与文件边界

### 3.1 前端目标

```text
router / navigation catalog
  -> route workspace page
     -> domain panels / editors / dialogs
        -> page-private application use case
           -> focused service client
              -> frontend-contracts domain types
```

1. 一个 route workspace 只拥有一个主要业务对象或一个紧密状态机；共享页面骨架可以复用，但不得以 `mode` 参数重新聚合六个不相关路由。
2. route page 负责路由参数、权限、加载与子组件编排；领域 panel 负责局部交互；application 用例只保留跨多个 API 的事务补偿、幂等或回滚编排。
3. service 文件按 API bounded context 拆分，原领域入口继续 re-export，避免一次性修改所有调用方。
4. 完全相同 API 类型归契约包；页面私有 view model 留在页面附近；不同投影禁止合成大量 optional 字段的“万能 DTO”。
5. 样式保持现有 token 和类名；本主线不做视觉重设计。

### 3.2 后端目标

```text
Controller
  -> stable facade / command service / query service
     -> domain validator / assembler / policy
        -> Mapper / external adapter
```

1. Controller 继续表达同一 REST 资源；拆 Service 不要求同步拆 Controller。
2. query/assembler 可以独立；写命令以业务事务为边界。禁止把一个原子写流程拆成多个独立事务。
3. 原 façade 在迁移期保留公开签名并委托新服务；调用方迁移完成、兼容测试通过后才删除无价值包装。
4. 工作流政策必须只有一个权威注册/解析入口；`ProjectAccessChecker` 继续作为第91条已验收的唯一项目范围入口，不新增平行 resolver；未知类型、缺失策略和重复注册全部失败关闭。
5. Mapper、DTO/VO、单实现安全/外部适配接口按框架和契约边界保留，不按文件短小合并。

### 3.3 明确保留项

- 所有已应用 Flyway migration、MySQL/H2 baseline、legacy migration 和版本化演示数据包。
- `WorkflowSubmitService`、`WorkflowApprovalService`、`WorkflowTaskService`、`WorkflowWithdrawService` 的独立事务状态机。
- `VirusScanner`、`DocumentRenderer`、`BidAwardProjectCreator`、`FileLifecycleGateway` 等安全、外部适配或跨域 port。
- 小型 MyBatis mapper、独立写入 DTO/VO、Vue 403/404/500 页面和 Capacitor Android 壳。
- `V2Stack` 与 `V2Cluster` 的轴向语义、`services/request.ts` 的请求协议、`fieldDrafts.ts` 的 IndexedDB repository。
- Dashboard façade、AutoPilot 兼容入口脚本、desktop launcher 单入口，以及需要版本可复现性的 v1/v2 demo 文件；没有新证据不删。

## 5. 不变量与结构完成标准

### 5.1 业务不变量

1. 所有现有 URL、深链、重定向、路由 meta、移动能力和权限可见性保持不变。
2. API 方法、路径、请求/响应字段、错误码和兼容历史值行为保持不变。
3. 租户、项目、角色、数据范围、文件权限和工作流专用入口全部 fail-close；拒绝顺序不静默放宽。
4. 金额精度、舍入、守恒、预算占用/释放、付款/冲销、库存移动平均价和成本事实不变。
5. 乐观锁、显式行锁、幂等键、状态转换、after-commit 事件和外部对象补偿顺序不变。
6. 离线草稿、同步重试、附件续传和历史候选“可读但不可重新选择”契约不变。

### 5.2 结构完成标准

1. 同一 Vue 页面不再由三个以上语义独立路由共享一个巨型 `mode` 状态机；确有共享价值的只保留壳和小型共享 panel。
2. 主要 route page 只负责编排，不再同时包含多个独立保存/提交/冲正状态机；超过 1,000 行但仍内聚的文件必须有保留裁决，不以数字判失败。
3. 高风险 Service 的 query、assembler 与 command/lifecycle 依赖分离；公开 façade 和事务入口清晰可审计。
4. 工作流业务类型→提交权限/专用入口政策只有一个权威注册表；项目范围继续只由现有 `ProjectAccessChecker` 提供，禁止产生第二实现。
5. `FileService` 与 `ProjectFileService` 不再形成双向依赖；文件索引、对象存储和 after-commit 语义保持一致。
6. 公共契约无重复定义；不同领域投影名称清晰；原公共 import path 在迁移期可用。
7. 每个被拆生产边界都有对应拆分后的 focused test；大型测试不存在依赖文件内执行顺序的隐式共享状态。
8. 不新增第三方运行或开发依赖；重复生产代码净减少，新增文件仅用于真实职责边界。
