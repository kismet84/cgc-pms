# 第53条主线 M6 分包结算与资金财务任务计划书

**Goal:** 在 M5 已正式收口基础上，将分包结算与资金财务域 16 条 Legacy 路由迁移为可验收的 Clean-room V2 闭环，保持分包任务、计量、结算、付款、费用、收入回款、发票、资金日记账、资金预测、会计凭证和月结的金额、来源、期间、审批、幂等与冲销均由服务端裁决。 **Architecture:** 复用现有 V2 公共壳、请求层、权限守卫、业务单据模板及既有后端 Controller/Service；按“契约、权限与只读金丝雀 → 分包任务与计量 → 结算 → 收付款、收入与发票 → 资金运营与会计期间 → 全量收口”串行推进；禁止新增平行资金账、前端权威金额计算、手工凭证生成入口或第二套审批、结算、应收应付与现金预测模型。

## 3. 已核实现状与启动缺口

- 分包任务复用 `/sub-tasks`，分包计量复用 `/sub-measures`；计量数量、单价、累计量和金额继续由服务端按合同清单裁决。
- 结算复用 `/settlements` 的列表、KPI、详情、批量明细、金额试算、来源、签证、付款、成本、附件、审批记录和提交端点。
- 付款、费用、收入与发票分别复用 `/pay-applications`、`/expenses`、`/revenue-operations`、`/invoices` 及既有 trace、审批、支付、冲销和单据生成能力。
- 资金运营、日记账、预测、凭证和月结复用既有 `/finance-operations`、`/cash-journal-entries`、`/cash-forecasts`、`/accounting-entry`、`/financial-close` 服务。
- 项目地图已确认分包计量、结算、付款资金、发票为 `Partial`；财务核算与月结、资金预测为 `Complete(P0)`。M6 只补 V2 用户入口和当前周期验收，不借迁移扩展 P1 能力。
- 当前 V2 导航为分包任务配置 `subcontract:task:query`，后端 `SubTaskController` 实际使用 `subtask:query`。030 必须以 Controller、角色菜单和真实普通角色样本确定权威码并修正契约。
- 路由台账中费用、收入、会计凭证、资金预测、财务月结 5 条权限为空，但 V2 导航已有候选权限。030 必须完成 Controller、菜单、导航、台账四方核对；证据不足标记“需要确认”，禁止管理员兜底。

## 4. 权威事实与复用边界

| 事实 | 权威来源 | V2 职责 | 禁止 |
| --- | --- | --- | --- |
| 分包任务与计量数量 | 分包任务、合同清单、计量服务 | 展示、提交业务输入、写后回读 | 本地累计数量或推进状态 |
| 结算金额与快照 | 结算金额策略、版本化快照 | 展示服务端字符串、触发受权动作 | 本地重算合同额、变更、扣款或应付 |
| 付款来源与可付余额 | `PaymentApplicationSourceService` | 选择业务单据、展示服务端余额 | 手输原始 ID、前端计算或占用额度 |
| 收入、应收与回款 | 收入回款服务 | 展示、受权写入、写后回读 | 平行应收账、前端核销 |
| 发票金额与校验 | 发票服务和文件安全链 | 展示校验结果、关联业务对象 | 浏览器伪造识别或校验结论 |
| 资金日记账 | 现金日记账及资金账户服务 | 只读余额、执行受权归档/冲销 | 前端累计余额、复制现金账 |
| 预测余额与缺口 | 资金预测版本和服务端日级计算 | 展示版本、提交措施、写后回读 | 客户端生成权威预测 |
| 会计凭证 | 业务写侧生成策略和凭证服务 | 复核、过账、驳回、重提、冲销 | 新增手工生成入口或本地借贷规则 |
| 会计期间与月结 | 月结检查、对账及期间服务 | 展示检查、触发受权关账/反结账 | 绕过检查、伪造期间状态 |

金额、数量、ID 使用稳定字符串；空值与 `0` 区分。所有写侧成功后必须重新读取服务端事实，不以 HTTP 成功或本地状态单独裁决。
