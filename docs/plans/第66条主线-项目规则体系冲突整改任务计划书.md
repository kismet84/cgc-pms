## 2. 权威层级与不变量

### 权威层级

1. 用户当前明确指令和仓库根 `AGENTS.md` 硬门禁。
2. `docs/standards/codex-task-execution-policy.md` 指定的专项唯一权威。
3. 命中任务后读取的专项 Skill。
4. Skill 明确引用的 references、配置、Schema 和批准来源。
5. 工程标准；只定义领域稳定规则，不复制执行流程或动态值。
6. 计划、质量报告、Prompt 和模板；只能记录事实、任务契约或引用权威规则。

同一层发生冲突时 fail-close，停止依赖该冲突执行写操作；由主线程对照当前代码、配置和测试确定权威并修正规则源。

### 不变量

- 不以超时、默认选项、兼容短语或计划状态替代用户明确授权。
- 生产、目标环境、凭据轮换、数据库写入和 Git 发布保持独立授权。
- 项目级业务数据必须同时满足租户与项目访问范围；前端隐藏不构成授权。
- 逻辑删除唯一性以当前 `active_unique_token` 实现和行为测试为准，不恢复已退役 `deleted_token`。
- AutoPilot 动态模型、推理等级、阈值、超时、评分版本和执行宿主只来自配置、Schema与批准来源。
- 项目业务产物留在 `docs/**`；插件自身治理产物留在插件 `artifacts/**`。
- 仓库不得要求所有环境都存在个人全局代理；自定义代理不可用时必须安全回退。
- 历史归档不追改；当前规则不得继续引用不存在或退役的入口。
- “可重建”“被忽略”或“可重新下载”不等于“无保留价值”；活跃依赖、离线缓存、增量数据库和最近成功构建默认保留。
- 清理依赖树前必须核实调用方、lockfile、实际 `storeDir` 和离线恢复能力；逻辑大小不得直接当作可释放物理空间。
- 索引和守护型目录的新鲜度以数据库文件、日志、锁/进程和补同步结果为准，不以父目录创建时间单独判定。
