## 3. 核心不变量

### 3.1 金额与状态

1. 同合同 `净 SUCCESS 实付 + APPROVING/APPROVED 未付余额` 不得超过合同 `currentAmount`；`REVERSED` 排除，同一申请已实付部分不得再次计入申请占用；DIRECT、费用、结算、计量和材料验收来源规则不变。
2. `PENDING_ARCHIVE` 只表示付款成功、现金证据待归档；项目预算和合同预算只在现金日记 `ARCHIVED` 后消费。
3. 冲销后原付款保留不可变历史；反向事实恢复来源实付和预算占用/消费，不删除原日记、原凭证或原证据。
4. `externalTxnNo` 同租户同数据幂等回读，异数据冲突；重复回调不重复付款、日记、凭证或预算消费。
5. 发票有效分配只能指向 `SUCCESS` 付款；付款进入 `REVERSED` 前必须证明不存在有效分配。

### 3.2 租户、权限与展示

1. 所有申请、合同、来源、预算、日记、发票、凭证和 Trace 关系必须同租户、同项目；跨租户按不存在处理。
2. DIRECT 每次保存和提交均执行服务端 `payment:direct` 精确授权；普通 `ADMIN` 不自动获得增强权限。
3. 企业现金余额只能由企业级数据范围读取；项目范围用户只能读取获授权项目事实，不能由聚合值反推公司余额。
4. Dashboard 和 V2 仅展示服务端金额字符串，不执行权威合计、状态修补或“缺失按零”。

### 3.3 历史与追溯

1. 当前指标读取当前事实；指定历史月份按逐指标来源矩阵读取不可变事实重算、既有当期汇总或明确不可用，不以今天的项目或合同状态改写历史。
2. Trace 任一入口都能到达项目、合同、成本科目/来源、申请、审批、付款、现金日记、发票、凭证和预算变动。
3. 冲销链同时展示原事实和反向事实；缺任何必要关系返回 `PAYMENT_TRACE_INCOMPLETE`，不得静默截断。

## 5. 验收矩阵

| 类别 | 必须覆盖 | 通过条件 |
| --- | --- | --- |
| 并发申请 | 同合同余额临界的两个申请同时提交 | 最多一方进入有效占用；累计不超过合同额；失败方无部分写入 |
| 并发付款 | 同合同两个申请同时 writeback | 成功实付累计不超过合同额；合同锁顺序一致；无死锁重试后重复事实 |
| 幂等 | 相同/冲突 `externalTxnNo`、重复审批回调、重复归档 | 同数据回读同一事实；异数据稳定冲突；预算/日记/凭证只生成一次 |
| 预算时点 | writeback、PENDING_ARCHIVE、ARCHIVED、REVERSED | 待归档不消费；归档消费；冲销后来源、项目预算、合同预算与现金事实守恒 |
| 发票 | PENDING/VERIFIED、已分配、解除后冲销、冲销后核验 | 有效分配阻止冲销；已冲销付款不能核验；失败整体回滚 |
| 权限/租户 | DIRECT、ADMIN、SELF、项目成员、跨项目、跨租户 | 无精确权限即拒绝；项目用户看不到公司余额；跨租户按不存在处理 |
| Dashboard | 当前/历史月，ACTIVE/SUSPENDED/CLOSED 项目，PERFORMING/SETTLING/SETTLED 合同 | 历史不受当前状态漂移影响；缺快照不按零；六项金额能从服务端事实对账 |
| Trace | EXPENSE/SETTLEMENT/SUB_MEASURE/MAT_RECEIPT/DIRECT 与冲销 | 任一入口双向完整；预算、发票、凭证、原/反向日记均可达；故意错链 fail-close |
| V2 | 五角色真实服务端 `FLOW-001` | 无全量 API mock；创建、审批、付款、归档、发票、凭证、Dashboard、Trace 写后回读一致 |
