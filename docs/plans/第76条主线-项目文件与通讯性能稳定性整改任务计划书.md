## 2. 当前调用链、影响面与测试缺口

### 项目文件中心

- 调用：`ProjectFileCenterPage.vue → project-files.ts → ProjectFileController.page() → ProjectFileService.page()`。
- 根因：`authorizedCatalogIds()` 无 `LIMIT` 读取全部候选；每个 BUSINESS 目录调用 `BusinessObjectAuthorizer.checkReadAccess("PROJECT_FILE", id)`，该链继续读取目录、项目和来源业务对象。
- 下游：页面 `total`、分页稳定性、来源业务权限交集、版本批量装配和项目范围。
- 现有覆盖：预览、导入、对账和单对象授权已有测试；缺少 `page()` 数据量、SQL 数量、精确 `total`、跨租户及拒绝项分页测试。

### 站内通讯

- 调用：`CommunicationController.messages() → CommunicationService.messages() → attachFiles() → attachments()`。
- 根因：`attachFiles()` 对消息逐条执行附件查询；附件索引已存在，问题不是缺索引。
- 草稿调用：`@Scheduled expireDrafts() → selfProvider.deleteDraft() → requireDraftForUpdate()`；行锁避免双写，但不能把已不存在/已发送转为幂等结果，且循环没有逐条异常隔离。
- 下游：消息历史、附件顺序、租户/成员边界、草稿附件级联删除、调度批次连续性。
- 现有覆盖：正常草稿过期删除、并发建会话和发送已有测试；缺少附件查询计数、删除竞态、已发送竞态和批次续跑测试。

`docs/codemap/codemap.json` 能回答模块、入口、下游和主要测试，但 `codemap.lock` 基线为 `fdbbc94b...`，早于当前 HEAD，且标记 backend/documentation stale。进入任何代码修改前必须先重生成代码地图三件套。

## 4. 不变量

- 项目文件 MANAGED 项满足租户、项目范围和 `project:file:query`；BUSINESS 项额外满足来源对象存在、来源权限和来源项目一致性。
- `total` 必须等于同一可见性谓词下的真实记录数；页面不得因先分页后过滤而少项、重项或泄露拒绝项。
- 数据库访问次数不得随目录记录数或消息条数线性增长；任何 `IN` 只允许使用单页内有界 ID。
- 通讯附件保持 `created_at,id` 顺序；无附件消息返回空数组；跨租户和非成员请求继续拒绝。
- 草稿被删除或发送属于清理任务的预期竞态，只跳过当前项并继续；对象存储、数据库或未知异常不得被 catch-all 吞掉。
- 草稿消息与附件级联仍在现有事务/补偿契约内；失败不得留下新增孤儿对象。
- 本计划全部验证限本地 dev/test/demo；不得把不存在的非本地环境作为前置或阻塞。

## 6. 实施包

### `FILE-PERF-01`：数据库级授权分页

最小文件候选：

- `backend/src/main/java/com/cgcpms/projectfile/ProjectFileService.java`
- `backend/src/main/java/com/cgcpms/file/auth/BusinessObjectAuthorizer.java`（仅在复用批量权限谓词确有必要时）
- 新增或扩展项目文件分页测试
- `docs/codemap/codemap.html`、`codemap.json`、`codemap.lock`

实施要求：

1. 删除 `authorizedCatalogIds()` 全量候选、逐条授权和全量 ID 拼接路径。
2. 在现有服务/JdbcTemplate 内形成一份可复用的可见性谓词，供 `COUNT(*)` 和页面数据 SQL 共用；MANAGED 与 BUSINESS 分支保持权限交集。
3. BUSINESS 来源按当前用户已有权限只启用允许的来源分支，并以 `EXISTS`/等价数据库谓词校验同租户、未删、来源对象及项目一致性。
4. 数据库先完成授权过滤，再按 `updated_at DESC,id DESC` 执行 `LIMIT/OFFSET`；`assemble()` 仅处理当前页并继续批量加载版本。
5. 不用候选窗口、分页后过滤、缓存、索引追加或 IN 分块掩盖根因。

退出门：1万条混合目录下首页和第100页查询数保持固定、total 精确、拒绝项不泄露、无随总量增长的参数集合，既有权限交集不变。

### `COMM-ATTACH-01`：消息附件批量加载

最小文件候选：

- `backend/src/main/java/com/cgcpms/communication/service/CommunicationService.java`
- `backend/src/test/java/com/cgcpms/communication/CommunicationServiceTest.java`

实施要求：

1. `messages()` 保持现有成员和消息查询；`attachFiles()` 提取最多100个消息 ID，一次查询 `sys_file`。
2. 按 `business_id` 分组，保持每组 `created_at,id` 顺序；缺少附件的消息填充空列表。
3. `draftRecord()` 的单消息附件查询不属于列表 N+1，可保留；不引入 FileService 重构、Mapper 或 JSON 聚合。
4. 查询参数严格限制在当前消息页，保留 tenant、business_type、deleted_flag 条件。

退出门：1、50、100条消息的 `messages()` SQL 数量固定为最多3次；内容、顺序、空附件、跨租户和非成员拒绝无回归。

### `COMM-DRAFT-01`：草稿清理预期竞态隔离

最小文件候选：

- `backend/src/main/java/com/cgcpms/communication/service/CommunicationService.java`
- `backend/src/test/java/com/cgcpms/communication/CommunicationServiceTest.java`
- `CommunicationMySqlConcurrencyTest.java`（仅在本地 MySQL 行锁语义需要补证时）

实施要求：

1. 保留每条草稿经 self proxy 进入独立事务及 `FOR UPDATE` 行锁的现有模式。
2. 清理循环只把 `COMMUNICATION_MESSAGE_NOT_FOUND`、`COMMUNICATION_MESSAGE_IMMUTABLE` 归为预期并发结果，记录并继续下一项。
3. 文件删除、数据库、认证上下文和未知异常继续上抛；禁止 catch-all 后伪报成功。
4. 汇总成功、已不存在/已发送、失败数量；使用一条结构化日志，不新增指标平台。
5. 当前单实例本地部署不引入分布式锁；若未来明确多实例，再单独评估领取机制。

退出门：首条候选在删除前被删除或发送时任务不抛错，后续草稿继续清理；意外文件删除失败仍使任务失败；附件无新增孤儿对象。
