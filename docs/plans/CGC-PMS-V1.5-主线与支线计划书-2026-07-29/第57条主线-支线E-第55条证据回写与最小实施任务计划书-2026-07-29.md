# 第57条主线支线E：第55条证据回写与最小实施任务计划书

**Goal:** 用第56条真实业务样本完成第55条非生产候选的唯一裁决，只实施证据证明必要的最小切片。

**Architecture:** 复用第55条原稳定键、既有业务对象和第56条正式证据；先裁决、后授权、再最小实施。禁止候选平台化、复制全局Issue、修改硬门禁或将外部依赖伪装成本地缺陷。

计划状态：`COMPLETED / REVIEW_PASS / 0_IMPLEMENTED / 0_READY`
阶段：`E0证据绑定 → E1～E7逐项裁决 → E8最小实施与复验 → E9治理回写`

## 1. 目标

使用第56条的真实业务样本，完成第55条非生产候选的最终裁决。只实施由真实样本证明必要的最小能力。

## 2. 启动前置

- 支线A通过。
- 第56条四类金丝雀通过。
- 第56条15条业务链完成。
- 第56条正式验收报告完成。
- 第56条相关P0/P1已关闭。
- 取证字段完整。

## 3. E1：A-02采购补货

检查第56条采购、库存、领料数据是否证明：

- 现有提前期和历史净领料不足。
- 存在明确需求对象。
- 存在可解释建议价值。
- 存在可量化误差指标。
- 存在人工覆盖需求。

若成立，最大实施范围：

- 一个工作日历。
- 一个需求对象。
- 只读建议。
- 人工覆盖。
- 回放和误差测试。

禁止：

- 自动下单。
- 多算法平台。
- 通用预测平台。
- 无法解释的黑盒建议。

若不成立：

- 有据关闭或保持冻结。
- 记录现有能力足以满足V1.5。

## 4. E2：A-03现场日报

从15条日报中识别最高频重复录入点。

最多实施一个：

- 项目成员只读联动。
- 当日质量问题只读联动。
- 单一设备事实联动。

禁止同时建设：

- 人员考勤。
- 设备平台。
- 天气平台。
- 定位。
- 离线同步。
- 统计平台。

若现有日报足够：

- 有据关闭或继续冻结。

## 5. E3：A-04 WBS

检查施工链是否存在无法由单前置FS表达的真实依赖。

只有成立时才允许实施：

- 多前置FS。
- 环检测。
- 日期一致性。
- 项目隔离。
- 最小迁移。
- 回滚。

不实施：

- 自动排程。
- 关键路径。
- 资源平衡。
- 跨项目依赖。
- 外部计划软件平台。

若样本均可由当前模型表达：

- 有据关闭或继续冻结。

## 6. E4：A-06报表

测量一个明确报表：

- 数据量。
- 查询时间。
- 导出时间。
- 内存。
- 文件大小。
- 角色。
- 权限。
- 口径。

若无明确超时或超限：

- 有据关闭异步平台化候选。

若存在：

- 只对该报表实施最小异步导出：
  - 提交；
  - 执行；
  - 下载；
  - 失败；
  - 过期；
  - 审计；
  - 权限；
  - 停用。

## 7. E5：A-09技术域

使用第56条的：

- 技术方案。
- 图纸。
- 会审。
- RFI。
- 回复。
- 技术交底。
- 施工依据。

验证是否存在现有对象无法表达的：

- 材料设备报审。
- 非RFI重大技术问题。

无独立缺口：

- 有据关闭或保持冻结。

有独立缺口：

- 优先扩展既有技术对象。
- 不新建第二套技术平台。
- 不同时引入BIM、AI审图或设计门户。

## 8. E6：A-07和A-10

由于依赖真实外部渠道或系统：

- 保持冻结。
- 记录明确前置。
- 不进入V1.5代码实施。
- 不阻塞V1.5开发版本。
- 每个未来方向保留独立决策门。

## 9. E7：AutoPilot观察

以支线A至D为一个完整周期，汇总：

- Ready质量。
- 环境失败。
- 重复路由。
- 无效验证。
- 返工次数。
- 失败分类。
- 任务持续时间。
- 验证成本。
- 最终评分。

裁决：

- 有稳定根因：拆一个最小改进。
- 无稳定根因：继续观察或有据关闭。
- 不得修改评分权重、状态机或硬门禁来制造达标。

## 10. 最小实施通用要求

每项实施必须包含：

- 稳定键。
- 真实样本。
- 复现步骤。
- 当前能力。
- 根因。
- 最小范围。
- 非目标。
- 数据模型影响。
- 权限影响。
- 迁移策略。
- 自动化测试。
- 浏览器验收。
- 回滚。
- 正式报告。

## 11. 退出门

第55条每个非生产事项均进入唯一状态：

- `IMPLEMENTED`
- `VERIFIED_RESOLVED`
- `FROZEN_WITH_EVIDENCE`
- `OBSERVATION_WITH_NEXT_CYCLE`

不得存在：

- 模糊“以后再看”。
- 无验收标准的候选。
- 无载体失败。
- 重复问题。
- 悬空问题。

## 12. 风险、失败分类与回滚

- 风险：样本不足仍进入实现、一个候选扩成通用平台、或新状态覆盖原稳定键。
- 失败分类：证据不足时保持`FROZEN_WITH_EVIDENCE`或带明确下一周期的`OBSERVATION_WITH_NEXT_CYCLE`；实现缺陷按统一失败分类阻塞对应最小切片。
- 回滚：未授权实现立即停止；代码或数据模型变更使用该切片预先定义的回滚；状态回写错误时恢复原稳定键、原载体和前一终态。
- 任何最小实施改变候选SHA后，旧自动化和浏览器证据失效，必须重新执行受影响支线及联合回归。
