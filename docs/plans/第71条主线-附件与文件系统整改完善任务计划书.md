## 1. 当前裁决与目标链

现有底座已具备统一元数据、MinIO、ClamAV、20MB入口限制、业务授权、五分钟签名URL和部分显式关系，但当前不是完整文件生命周期：Controller与服务契约漂移，数据库与对象存储双写缺补偿，软绑定父对象删除不完整，显式文件关系的不可变语义不一致，V2各页面能力碎片化。

目标链：

```text
业务对象存在且可写
  → 服务端归一 businessType/documentType
  → 业务权限、项目范围、状态与证据阶段校验
  → 大小、扩展名、MIME、真实格式与病毒扫描通过
  → tenant-scoped对象写入
  → sys_file元数据原子落库或失败补偿
  → 列表只返回必要元数据
  → 审计下载入口签发短期URL并保留原文件名
  → 提交/归档/定版后按业务规则不可变
  → 删除或父对象删除进入可重试对象清理
  → DB↔MinIO对账、备份与恢复验证
```

## 4. 核心不变量

### 4.1 租户与对象身份

1. 新对象键必须包含不可伪造的当前租户维度；`sys_file.tenant_id`、对象键租户、业务对象租户必须一致。
2. 下载、列表、删除、复扫、对账和清理均先按当前租户定位元数据；跨租户统一按不存在处理。
3. 历史对象以数据库已持久化`bucket_name/storage_path`为读取事实；未完成清单、备份和回读前不批量改键。
4. 同租户同业务对象同内容的活动重复只保留一个权威元数据；跨租户绝不共享生命周期。
5. 每条新元数据独占一个包含预分配`fileId`的对象键，目标格式为`tenants/{tenantId}/{BUSINESS_TYPE}/{businessId}/files/{fileId}/{sha256.ext}`；失败补偿不得删除另一请求已成功持有的对象。

### 4.2 上传与安全

1. `businessType`、`documentType`在授权、持久化、查询和业务门中使用同一规范值与同一兼容矩阵。
2. 文件大小、扩展名、声明MIME、真实格式和病毒扫描全部在服务端成立；扫描器不可用、感染或未知均fail-close。
3. 上传事务失败时，元数据和对象最终必须同时不存在；重复请求不得生成多条活动元数据。
4. `CLEAN`只能来自真实扫描成功或可信服务端生成文件；不得由SQL、前端字段或历史默认值伪造。

### 4.3 读取、审计与最小披露

1. 列表只返回页面需要的文件ID、原名、大小、内容类型、文档类型、扫描状态和创建事实，不返回bucket、storage path、内部文件名或签名URL。
2. 每次下载/预览签发均重新校验租户、业务对象、项目范围、权限和`CLEAN`状态，并记录真实业务类型、业务ID、文件ID、结果和稳定错误码。
3. 预签名URL保持短期 bearer 能力；过期后必须重新授权，不把签名URL长期持久化到业务表或前端缓存。
4. 下载文件名使用安全编码后的原始文件名；预览与下载语义明确，不依赖浏览器偶然行为。

### 4.4 不可变、删除与恢复

1. 已提交、审批中、已批准、已归档、已定版、已作凭证或已生成文档的附件按业务规则不可变；通用删除不得绕过显式关系。
2. 父对象删除必须在同一事务内冻结附件处置事实；事务提交后对象清理可重试且幂等，失败不得静默丢失。
3. 对象不存在、元数据不存在、关系跨租户、重复活动键和删除待清理均可被对账发现；修复动作必须先预览。
4. 备份验证必须同时证明数据库元数据、对象内容及可恢复映射，不以“目录非空”代替恢复成功。

### M3：G3 服务端文件生命周期闭环

#### M3.1 上传、规范化与对象一致性

- 在权限与持久化前统一规范业务类型和文档类型；文档类型矩阵由一个服务端事实入口维护。
- 新上传先预分配`fileId`，再使用含租户和`fileId`的独占对象键；同租户同业务对象同内容的并发请求由数据库或等价原子门裁决，失败请求只能清理自身对象。
- 普通上传复用生成PDF已有的事务回滚对象清理；补偿失败进入可重试清理事实，不只记日志。
- OOXML校验使用JDK ZIP能力检查固定`[Content_Types].xml`及`word/xl/ppt`根目录，并限制entry数量与展开总量；原名移除全部控制字符，仅用于展示/下载，不参与对象路径，不新增解析依赖。

#### M3.2 不可变关系、父对象删除与对象清理

- 通用删除先检查业务状态和所有显式文件关系；投标`FINAL`、付款归档证据、生成文档等不可通过`DELETE /files/{id}`移除。
- 可删除父对象统一调用文件生命周期服务；DB事务只冻结逻辑删除和清理事实，对象删除在提交后幂等执行并可重试。
- 文件级联不得通过可空依赖静默降级为“只删DB”；生命周期服务不可用时父对象删除整体失败。
- 清理任务按有界批次执行，记录成功/失败/重试；对象已不存在视为幂等成功，租户或路径不匹配立即fail-close。
- 历史无租户路径在物理删除前必须统计全部活动元数据引用；引用数非零或归属不唯一时只报告，不删除对象。
- 对账报告区分元数据孤儿、对象孤儿、关系断链、跨租户键冲突和待清理，不自动扩大删除范围。

#### M3.3 读取、签名URL与审计

- 列表不再生成预签名URL；上传响应也只返回必要元数据，页面需要打开文件时再调用审计URL端点。
- 下载审计记录真实`businessType/businessId/fileId`和业务错误码；失败同样留痕，并明确事件含义是“授权并签发下载链接”，不是对象字节已被用户实际读取。
- 对象签名使用public endpoint但不改写签名结果；响应安全保留原文件名，明确inline/attachment策略。
- 获取URL前必要时验证对象存在；对象缺失返回稳定一致性错误并进入对账，不返回必然404的URL。

#### M3.4 病毒复扫、健康与恢复能力

- 提供只读预览、批次大小、断点、失败重试和汇总结果明确的复扫入口；只有实际`CLEAN`结果才能更新状态。

## 9. 风险、恢复与金丝雀矩阵

| 风险 | 首次停止条件 | 恢复/回滚方式 | 禁止项 |

| 上传补偿 | DB失败后对象仍残留且重试事实丢失 | 停止扩大上传；恢复事务前版本并保留孤儿清单 | 静默忽略、仅清空bucket |
| 删除补偿 | 对象删除失败或误指向其他租户路径 | 立即停用清理执行；按元数据和备份恢复；保留删除事实 | 无租户校验批量删除、递归清桶 |
| 不可变关系 | 投标/付款/生成文档任一引用被逻辑删除 | 停止发布；从备份恢复对象和元数据；修复删除门后重验 | 删除关系规避FK、伪造新文件替代历史 |
| 下载契约 | 业务页因列表不再带URL而断链，或审计丢失 | 回退前后端同一契约版本；不恢复内部字段长期暴露 | 前端拼接MinIO URL、长期缓存签名URL |
| 父对象级联 | 父对象回滚但附件已删，或父对象删除后附件无处置 | 事务回滚；从备份恢复对象；修复提交后动作顺序 | 事务提交前物理删对象 |
| 复扫 | 扫描器不可用、感染、对象缺失或批次中断 | 保存游标和逐对象结果；保持非CLEAN不可下载；恢复后续跑 | SQL批量标CLEAN、跳过感染对象 |
| 前端统一 | 共享交互改变业务状态语义 | 回退受影响页面，保留统一service；逐模块复验 | 一次重写全部业务页、前端放宽权限 |
| 备份恢复 | 恢复对象无法与元数据对齐或哈希不一致 | 保留源备份，删除隔离恢复副本后重演 | 在原bucket直接覆盖演练 |
