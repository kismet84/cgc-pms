# 第80条主线：CI 全量验证分层与后端测试门禁提效

**Goal:** 清理 E2E 与全量 CI 中已经失效、重复或证据语义错误的验证，修复页面变更可能只命中默认跳过 live spec 的门禁缺口，并在不降低后端覆盖率、MySQL 并发验证和同 SHA 合并安全的前提下缩短 CI 关键路径。 **Architecture:** 复用现有 GitHub Actions、Playwright、Vitest、Maven Surefire/JaCoCo、H2 legacy 回归和 MySQL 专项测试；将浏览器验证分为“确定性 mock 契约”和“本地真实运行态验收”，将后端完整 `verify` 与历史顺序敏感复验并行；以 `pr-push-evidence` 校验同 SHA push 全量证据，以受保护分支设置决定新复用逻辑是否允许启用。不新增测试框架、第三方 CI 平台、服务编排层或生产环境流程。

## 1. 结论与整改原则

- E2E 的 `1 skipped` 来自 `m8-root-rehearsal.spec.ts`：该测试仍有价值，但依赖专用 root rehearsal 前置，不应混入普通 migration gate 后再长期跳过。
- 不能直接删除完整 E2E、后端顺序敏感门禁、MySQL 专项或覆盖率门禁。问题是选择器、分层、证据命名和串行调度，不是测试总量本身。
- 可直接删除的是永久无效的 `.shell-placeholder` 计数断言；可更新的是已过时的 `HealthPage` 隔离底座文案契约；可去重的是 `m4-variation-bid` 与 `engineering-tender` 的重复投标页覆盖，但必须先让后者进入正式 CI 选择集。
- mock Playwright 套件只证明前端路由、DOM、交互、无障碍和请求契约，不证明真实后端、MySQL、权限或状态机。真实运行态验收继续由显式 `V2_LIVE_*` 本地任务和专项脚本承担。
- backend-test 优先做零语义损失提效：顺序复验独立并行、该复验跳过重复 JaCoCo、保存成功态耗时证据、减少重复 Spring 属性造成的上下文碎片。禁止先提线程数或降低覆盖率。
- PR push 复用新逻辑只在保护规则 fail-close 后启用。当前变量 `CI_PR_PUSH_REUSE_ENABLED` 未设置；因此所有 PR 继续全量执行，这是安全默认，不是故障。

## 3. 目标、非目标与不变量

### 目标

1. 所有普通 E2E 运行结果不再包含“按设计永久 skip”的测试。
2. 页面变更不得映射到默认 skip 的 live spec 后仍显示门禁成功。
3. mock 浏览器契约、真实运行态 E2E、后端 H2、MySQL 与供应链证据名称和边界一致。
4. backend 完整回归与历史顺序敏感复验并行，消除重复 coverage 成本。
5. 同 SHA push CI 可被可信 PR verifier 复用，但任何 verifier 异常、fork、控制面变更或保护规则缺失都 fail-close 到全量 CI。
6. 从最近 10 次成功 run 建立可重复耗时基线，并以至少 5 次连续成功 run 验收提效，不用单次最快值裁决。

### 非目标

- 不删除业务行为测试以追求数量下降。
- 不把全部 `@SpringBootTest` 一次性改成 slice tests；先测量最慢类和上下文碎片，再处理头部热点。
- 不提升 Maven 并行度到 2 以上，不改变 fork 模式，不并发执行存在共享状态的类。
- 不改 H2 legacy migration，不用 H2 绿灯替代 MySQL，不扩大 MySQL 到全套后端测试。
- 不降低 JaCoCo 阈值，不取消依赖扫描、SQL 安全、workflow contract 或 supply-chain gate。
- 不新增 CI SaaS、测试框架、缓存服务或生产发布步骤。

### 不变量

- `./mvnw -C verify` 仍是后端完整 H2 回归与 JaCoCo 权威入口。
- MySQL 五类专项保持独立、真实 MySQL 服务和现有环境开关。
- 所有 required context 的新增、改名、删除先更新代码与 verifier，再更新分支保护，最后才允许启用复用变量。
- 任何同 SHA 复用都必须校验仓库、HEAD SHA、分支、事件、run 结论、完整证据 job 集和 GitHub Actions app 身份；仅凭同名 check 不足。
- 控制面文件变更必须强制全量：`.github/workflows/**`、`.github/actions/**`、`scripts/ci/**`、相关 verifier、测试选择器和门禁配置。

## 4. 目标验证架构

| 层级 | 入口 | 证明内容 | 不证明内容 |
| --- | --- | --- | --- |
| L1 静态/单元 | lint、type-check、Vitest、Maven unit/integration | 代码、类型、组件和服务逻辑 | 浏览器、真实 MySQL、部署 |
| L2 浏览器契约 | `test:e2e:contract` | V2 路由、DOM、交互、A11y、API 请求/响应契约 | 真实 backend、数据库和权限实现 |
| L3 本地 live | 显式 `test:e2e:live:*`、M8 rehearsal | 本地真实 frontend/backend/API/权限/状态机 | 非本地或生产发布 |
| L4 后端完整 | `mvn verify` | H2 legacy 回归、完整 Java suite、JaCoCo | MySQL dialect、锁与 migration 真实性 |
| L5 MySQL 专项 | `backend-test-mysql` | 真实 MySQL migration、租户范围、关键并发 | 全业务浏览器旅程 |
| L6 交付证据 | push full CI + PR verifier/必要 PR full CI | exact SHA 的门禁集合与合并保护 | 合并后源码之外的生产状态 |

目标 CI 依赖关系：

```text
pr-push-evidence
├─ backend-test-full ───────────────┐
├─ backend-order-sensitive ────────┤
├─ backend-test-mysql ─────────────┤
├─ frontend lint/type/build/unit ──┼─ evidence set
├─ frontend-v2 policy ─────────────┤
├─ browser-contract ───────────────┤
├─ dependency/supply-chain/sql ────┘
└─ build-summary (display only, never evidence)
```

## 9. 失败分类

所有失败只能归入以下唯一分类，并记录责任动作与最小复验：

| 失败分类 | 本计划示例 | 动作 |
| --- | --- | --- |
| `tool_config` | workflow YAML、job needs、required context 名错误 | 修配置与契约测试 |
| `tool_invocation` | Maven 参数引号、Playwright spec 路径错误 | 修调用，不改业务代码 |
| `environment_prerequisite` | runner 镜像、浏览器、容器或本地 live 前置缺失 | 恢复前置后原命令复验 |
| `ready_issue_config` | 页面映射落到默认 skip live spec、evidence set 漏 job | 修 Issue/门禁配置，fail-close |

| `quality_or_security` | 测试真实失败、未处理 API、覆盖率下降、verifier 可绕过 | 修根因并完整复验 |
| `unknown` | 证据不足且不能归类 | 保持阻塞，补证据后重分类 |

## 10. 风险、停止条件与回滚

| 风险 | 停止条件 | 回滚/恢复 |
| --- | --- | --- |
| E2E 去重误删独有业务覆盖 | 删除前后场景矩阵无法一一对应 | 恢复被删场景；宁可暂时重复 |
| contract job 去服务后暴露隐式真实请求 | 出现未处理 API 或登录跳转 | 修 mock 边界；确需真实服务则独立 integration job |
| Spring 属性清理改变上下文 | 定向或 full verify 出现行为差异 | 回退该属性批次，不扩大修改 |
| order job 并行产生资源竞争 | 并行后 flaky 或 runner 资源不足 | 保留独立 job，限制并发或暂时恢复串行依赖 |
| required context 改名导致保护悬空 | API 回读缺 context 或错误 app id | 立即恢复旧 required set，变量保持 false |
| verifier 失败但旧 job skipped 被视为成功 | `pr-push-evidence` 未成为 required | 禁止启用复用；先修保护规则 |
| 单次性能样本误导 | 只出现一次异常快/慢 run | 使用至少 5 次中位数与 P90，不继续盲调 |

最小总回滚顺序：先将 `CI_PR_PUSH_REUSE_ENABLED=false` 或删除变量，使 PR 恢复 full；再恢复 required context 兼容集合；最后回退 job 拆分。任何回滚不得绕过保护、强推或删除测试证据。
