# 第55条主线支线：业务编码自动编号治理任务计划书

**Goal:** 对当前 V2 业务域 30 个编码、编号或版本字段完成逐项分类与治理：22 项内部业务编码改为服务端自动生成，8 项外部、版本、关系或期间字段保持人工语义，消除前端自编和服务端信任客户端内部编号。

**Architecture:** 新增最小 `BusinessCodeGenerator`，规则使用编译期枚举白名单，按现有数据库唯一粒度查询包含软删的历史最大号，生成 `前缀-yyyyMMdd-三位序号`；各业务服务在事务内最多重试 3 次，数据库唯一约束最终裁决。创建忽略客户端内部编号，更新冻结原编号，V2 只展示服务端生成结果。MySQL/H2 同步新增 `V235` 仓库编码唯一约束。禁止新增编号后台、DSL、前端算法、外部编号伪造或历史编号改写。

计划状态：`S0-S4_LOCAL_COMPLETE / LOCAL_ACCEPTED / SAME_HEAD_CI_PENDING`
稳定键：`BUSINESS-CODE-AUTOMATION-GOVERNANCE`

## 1. S0 事实冻结

当前 30 项均未由服务端自动生成，原“27 个内部候选 + 3 个版本字段”前提不成立：

| 分类 | 数量 | 字段 | 裁决 |
| --- | ---: | --- | --- |
| 内部自动编号 | 22 | 仓库、招采、退货；计划、计划期间、进度纠偏；质量计划、检查、后果；技术方案、会审、RFI、交底、归档；收尾、分项验收、竣工验收、质保、缺陷、移交；完工预测、成本纠偏 | `AUTOMATED`；服务端生成，前端不可编辑 |
| 外部/契约人工 | 3 | 供应商报价、图纸编码、合同清单编号 | 保持人工；不得由系统伪造外部事实 |
| 版本语义 | 3 | 预算版本号、目标成本版本号、图纸版本号 | 保持既有版本链；不得改为日流水 |
| 关系/期间语义 | 2 | WBS任务编码、计量期间编码 | 保持人工；前者被父/前置任务引用，后者按合同唯一 |

实施前证据边界：

- 典型 DTO 使用 `@NotBlank`，V2 表单使用 `required`，服务层直接保存输入值。
- 现有自动计量单 `measureCode` 不等于计划内的计量期间 `periodCode`。
- 多数目标域为 JDBC 直写，不能假定已有实体 Mapper、唯一约束或软删查询。
- 仓库编码原仅有 `NOT NULL`，本轮新增项目粒度唯一约束。

### 1.1 S1 规则冻结

| 业务域 | 字段 | 前缀 | 唯一粒度 |
| --- | --- | --- | --- |
| 库存/供应商 | `warehouseCode/sourcingCode/returnCode` | `WH/SRC/SRT` | 仓库按租户+项目；招采、退货按租户 |
| 进度 | `planCode/periodCode/actionCode` | `SCH/SPD/SCA` | 租户+项目 |
| 质量 | `planCode/inspectionCode/consequenceCode` | `QPL/QIN/QCO` | 租户+项目 |
| 技术 | `schemeCode/reviewCode/rfiCode/disclosureCode/archiveCode` | `TSC/TRV/RFI/TDS/TAR` | 租户+项目 |
| 收尾 | `closeoutCode/acceptanceCode/acceptanceCode/warrantyCode/defectCode/transferCode` | `PC/SA/FA/WAR/DEF/ATR` | 复用现有租户级编码唯一约束 |
| 成本 | `forecastCode/actionCode` | `CFT/CCA` | 租户+项目 |

统一规则：查询含软删历史，编号不复用；保留非标准历史编号；并发唯一冲突最多换号重试 3 次；单作用域单日前缀最多 999 条，超过后失败关闭。

## 2. 范围与非目标

范围：

1. 维护上述 30 项唯一分类。
2. 为 22 项内部候选补齐前缀、租户/项目/合同粒度、软删复用、冲突重试和历史兼容规则。
3. 规则获批后，服务端忽略客户端内部编号并返回实际值，V2 只展示写后回读结果。
4. 每个实施域覆盖生成格式、跨租户、唯一冲突、软删和回读。

非目标：

- 不修改主数据、系统管理、外部/契约编号或版本链。
- 不新增通用编号后台、DSL、前端算法或依赖。
- 不改历史数据，不放宽唯一约束。
- 不修改 8 项保留人工语义的字段。

## 4. 实施不变量

1. 内部编号仅由服务端生成；前端不计算、不预占。
2. 唯一粒度必须与数据库约束一致，不能用租户级流水替代项目/合同级规则。
3. 生成器只负责候选号；每个业务服务捕获唯一冲突并最多重试 3 次。
4. 生成查询不附加删除条件，已删除编号不复用。
5. 外部/契约编号、版本号、WBS关系键和计量期间保持原语义。
6. 创建成功后写后回读，页面只展示服务端返回值。

## 6. 风险与回滚

| 风险 | 控制与回滚 |
| --- | --- |
| 外部编号或版本号被误自动化 | 分类门禁止进入实现；回退目标域改动，不改历史值 |
| 唯一粒度错误 | 先以业务约束和数据库索引双证据冻结规则 |
| 并发重复 | 业务事务内有限重试，数据库唯一约束最终裁决 |
| 软删冲突 | 生成器查询包含软删历史，保持不复用 |
| 范围膨胀 | 不建编号平台；一次只实施一个规则完整的业务域 |
