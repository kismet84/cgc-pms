# 第75条主线：站内即时通讯系统

**Goal:** 在 `master@9e6e6e6f5bd56b3f86e1783f31575ddadcf64d91` 审查基线上，新增同租户启用用户的站内即时通讯能力，完成“一对一/群聊 → 文本与附件发送 → 实时提醒 → 历史补拉 → 未读管理 → 群成员治理”本地闭环，并保证租户隔离、成员授权、附件安全、发送幂等和失败恢复。 **Architecture:** 保留现有 `sys_notification` 系统通知中心，不将聊天数据塞入通知表；新增最小会话、成员、消息三表，采用 REST 发送、SSE 接收，复用 HttpOnly Cookie、CSRF、`apiRequest`、MinIO、ClamAV、`sys_file`、下载审计和对象补偿任务。附件直接绑定消息，不新增附件关系表、WebSocket、消息队列、第二文件系统或独立通讯微服务。

## 1. 产品决策

| 项目 | 冻结方案 |
| --- | --- |

| 会话类型 | 一对一及群聊 |
| 用户范围 | 同租户启用用户 |
| 功能授权 | RBAC控制 |

## 2. 范围与非目标

### 2.1 范围

- 同租户通讯用户目录、私聊唯一会话、群聊创建及成员治理。
- 消息草稿、发送幂等、会话历史、阅读游标和未读汇总。
- REST命令、SSE实时提示、断线后的历史补拉。
- 通讯附件上传、扫描、下载、失败补偿和草稿清理。
- V2桌面及移动端通讯页面、群管理、顶栏未读入口。
- MySQL/H2等义 migration、RBAC、操作审计、自动化及本地真实链路验收。

### 2.2 非目标

- 修改或替换现有系统通知中心。
- 在线状态、正在输入、消息撤回、编辑、删除、全文搜索、置顶和免打扰。
- 语音、视频、表情商店、机器人、外部联系人或跨租户通讯。
- 端到端加密、消息队列、Redis Pub/Sub、多节点实时分发或 WebSocket。
- 第二文件主表、第二对象桶、分片上传或扩大单文件20MB限制。
- 非本地环境测试、验收、部署或发布。

## 3. 核心不变量

### 3.1 租户与成员

- 所有表、查询、唯一键和更新条件包含 `tenant_id`。
- 租户和操作者只取认证上下文，禁止客户端传入。
- RBAC只控制功能入口；会话成员身份控制消息和附件访问。
- `ADMIN/SUPER_ADMIN`非会话成员也不得读取聊天内容。
- 跨租户、非成员或越过加入边界的访问统一返回不可枚举的404。
- 停用用户不进入通讯录，不接收实时推送，不允许新建会话或加入群聊。

### 3.2 消息与阅读

- 消息正文按纯文本处理，最多4000字；空正文且无附件拒绝。
- 会话行保存 `last_seq`；发送、加人、移人、转让群主都锁定会话行。
- 消息 finalize 时分配连续 `seq`；`DRAFT`不进入历史、未读或 SSE。
- `clientMessageId`保证重试幂等；相同ID不同载荷返回409。
- 阅读游标只能单调前进，不能超过当前可见最大序号。
- 未读统计排除本人消息及加入前消息。

### 3.3 群治理

- 群最大100人，始终恰有一个群主。
- 群主可修改群名、任免管理员、移除成员、转让群主和关闭群聊。
- 管理员只能增删普通成员和修改群名，不能操作群主或其他管理员。
- 普通成员只能发送、阅读和退群。
- 群主必须先转让或关闭群聊才能退出。
- 新成员设置 `joinedSeq = lastSeq + 1`；退出或移除后立即失去会话、历史、附件和 SSE 访问。
- 重新加入重新计算 `joinedSeq`，不得恢复旧历史。
- 一对一成员固定，不支持增删、改角色或自聊。
- 关闭群聊后历史只读、附件保留，不做物理删除。

## 4. 数据模型与公开契约

### 4.1 数据模型

- `communication_conversation`：租户、类型、群名、私聊规范化用户对、最后消息序号/时间、状态。
- `communication_member`：会话、用户、角色、加入/离开序号、最后阅读序号、有效状态。
- `communication_message`：会话、发送人、`DRAFT/SENT`、会话序号、正文、客户端幂等ID、创建时间。

关键唯一约束：

- `tenant_id + direct_pair_key`
- `tenant_id + conversation_id + user_id`
- `tenant_id + conversation_id + seq`
- `tenant_id + sender_id + client_message_id`

私聊双方ID按数值升序生成 `direct_pair_key`；并发创建冲突后回读唯一会话，不创建重复对话。

### 4.2 API

用户与会话：

- `GET /communications/users`
- `GET|POST /communications/conversations`
- `PATCH /communications/conversations/{id}`
- `POST|DELETE /communications/conversations/{id}/members`
- `PUT /communications/conversations/{id}/members/{userId}/role`
- `PUT /communications/conversations/{id}/owner`
- `POST /communications/conversations/{id}/leave`
- `POST /communications/conversations/{id}/close`

消息：

- `GET /communications/conversations/{id}/messages`
- `POST /communications/conversations/{id}/drafts`
- `POST /communications/messages/{id}/send`
- `DELETE /communications/messages/{id}`，仅取消本人草稿
- `PUT /communications/conversations/{id}/read`
- `GET /communications/unread-count`
- `GET /communications/stream`

前端公共类型：`CommunicationUserSummary`、`ConversationSummary`、`MessageRecord`、`AttachmentRecord`、`CommunicationUnreadCount`。所有数据库ID及消息序号按字符串传递。

### 4.3 RBAC

- `communication:view`：读取通讯入口、会话、消息、未读和 SSE。
- `communication:send`：查询可通讯用户、创建私聊、创建草稿、上传附件和发送。
- `communication:group:manage`：创建群聊；群内管理仍受群角色限制。
- `ADMIN/SUPER_ADMIN`可绕过功能权限，不可绕过成员数据权限。

## 5. 附件与实时链

### 5.1 附件

1. 创建消息 `DRAFT`并取得消息ID。
2. 每个附件独立调用现有 `/files/upload`，绑定 `businessType=COMMUNICATION_MESSAGE`、`businessId=messageId`、`documentType=CHAT_ATTACHMENT`。
3. `BusinessObjectAuthorizer` 校验同租户、本人草稿、有效成员、草稿状态和附件数量。
4. finalize 原子校验所有附件为同租户、同消息、扫描 `CLEAN`且不超过5个，再分配 `seq` 并转为 `SENT`。
5. 发送后禁止增加或删除附件。
6. `DRAFT` 24小时过期，附件通过现有逻辑删除和持久化对象任务清理。

允许格式继续使用现有 PDF、JPEG、PNG、GIF、WebP、DOCX、XLSX、PPTX、TXT、CSV 白名单，不新增压缩包、可执行文件或旧版 Office。

### 5.2 SSE

- 使用同源 HttpOnly Cookie，不在URL携带Token。
- 事件只传会话ID、消息ID、序号和刷新动作，不传正文、用户资料或预签名URL。
- 事务提交后才推送；回滚不得产生事件。
- 推送前重新检查接收人启用状态和有效成员关系。
- 每个租户用户最多5个连接，支持多标签页；25秒心跳，异常、超时和退出时清理。
- SSE只作提示；进程重启、漏事件或断线后，前端通过 REST 按序号补拉并重新计算未读。
