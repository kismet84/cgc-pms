## 3. 权威成本事实节点

| 来源 | 唯一首次入账节点 | 禁止重复节点 |
| --- | --- | --- |
| `MAT_RECEIPT` | 材料验收终审通过 | 采购订单、付款、现金、凭证 |
| `MAT_REQUISITION` | 领料审批且实际出库完成 | 库存查询、付款、凭证 |
| `SUB_MEASURE` | 分包计量终审通过 | 分包结算、付款、凭证 |
| `VAR_ORDER` / `CT_CHANGE` | 对应变更终审通过 | 合同变更入账后的付款/凭证 |
| `CT_CONTRACT` | 非主合同终审的锁定成本事实 | 分包计量实际成本不得复写锁定事实来源 |
| `QS_CONSEQUENCE` | 金额后果终审通过 | 整改、付款、凭证 |
| `OVERHEAD_ALLOCATION` / `FINANCE_COST_ALLOCATION` | 分摊审批通过 | 来源凭证/费用申请本身不得再次计成本 |
| 重算/关闭后调整/冲销 | 对原事实生成等额正反向调整 | 直接 UPDATE/DELETE 原 `cost_item` |

## 4. 数据与工作流设计

1. 扩展规则版本生命周期与审批快照；规则、映射均从属同一版本，校验通过后才可提交。
2. 为 `cost_item` 增加分类状态、原匹配科目、规则/版本、覆盖与调整来源元数据；历史行仅补分类元数据，不改金额、来源或过账状态。
3. 新增项目配置申请、分类覆盖、历史重算批次/明细；批次冻结 cutoff 与旧快照，审批后按每条差异写负旧正新事实。
4. 新增 `COST_RULE_PLAN`、`COST_PROJECT_CONFIG`、`COST_RECALCULATION`、`COST_POST_CLOSE_ADJUSTMENT` 与转入/分摊冲销工作流；均为 `COMPANY_FINANCE` 一级审批，`preventInitiatorApproval=true`，不要求项目成员身份。
5. 所有业务候选 API 返回可读编码/名称并按租户、项目、状态、COST 末级和数据域过滤；历史失效值单独返回为禁选展示。

## 5. 非目标

- 不把会计科目目录退回仅成本目录，不把资产、负债、收入、结算或应收类科目纳入成本配置。
- 不建设第二套成本账本、通用规则引擎、通用 ETL 或外部财务系统。
- 不从付款、费用、结算、现金日记或会计凭证重复生成已由上游权威节点确认的成本。
- 不覆盖、删除、改科目或改金额来“重算”历史；不为演示直接修改业务表。
- 不扩大非财务写权限，不使用管理员绕过申请人与审批人分离。
