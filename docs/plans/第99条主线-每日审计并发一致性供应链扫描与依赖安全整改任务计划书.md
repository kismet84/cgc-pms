## 3. 设计冻结

### D01 付款并发契约

- GET/列表 VO 必须返回 `version`，编辑器保存该快照，PUT 必须提交 `expectedVersion`；服务禁止用数据库最新版本覆盖请求版本。
- `updateById(app)` 返回值必须等于 1；请求版本与当前版本不等或更新 0 行均复用 `PAY_APP_STATUS_CONFLICT`，不得再造并发错误码。
- 既有草稿更新通过同一 PUT 携带来源白名单；申请头 CAS 更新与来源校验/替换加入同一事务。来源为空数组代表明确清空并按金额规则校验，字段缺省只保留旧调用兼容，不作为 V2 页面路径。
- 冲突响应不得返回成功 DTO；前端提示“数据已被更新，请刷新后重试”，并重新加载服务端权威记录。
- 不增加悲观锁、全局锁或数据库列；复用既有 `@Version`。

### D02 构建产物扫描契约

- 定时后端复扫必须先以 `${GITHUB_SHA}` 对应源码解析/构建 JAR，再扫描 JAR 解包后的完整运行时依赖；不得用源码目录 0 漏洞替代制品结论。
- 抽取或扩展一个 `scan-backend-artifact` 权威入口，由完整 CI 与定时任务共同调用；Trivy 版本/digest、严重级别和忽略规则只有一份事实源。
- 下列任一条件失败关闭：JAR 不存在、未绑定当前 SHA、`BOOT-INF/lib` 库数量为 0、Maven/Trivy 报依赖版本无法确定、HIGH/CRITICAL 命中或 Trivy 日志/报告生成失败。
- scheduled 只保留当前 SHA JAR、库计数和 Trivy 日志/报告证据；SBOM 继续由完整 CI 生成并作为最终制品证据，不在定时任务复制一套生成链。
- 源码 `fs` 可保留为快速前置检查，但不能作为定时 backend dependency rescan 的完成证据。

### D03 模板安装四态契约

| 后端结果 | 条件 | 前端提示语义 |
| --- | --- | --- |
| `BOUND` | 首次创建系统默认绑定 | 已安装并设为系统默认 |
| `UPDATED_SYSTEM` | 系统默认真实切换到新版本 | 系统默认已更新 |
| `UNCHANGED_SYSTEM` | 已绑定同一系统版本且无写入 | 已安装，系统默认未变化 |
| `PRESERVED_CUSTOM` | 租户自定义绑定保持不动 | 已安装，租户自定义默认保持不变 |

### D04 Tomcat 窄升级契约

- 优先使用 Boot 支持范围内的 Maven 属性将嵌入式 Tomcat 固定到 `10.1.59`；禁止借机升级 Boot 4 或拆分依赖 BOM。
- 最终 JAR 只能包含同一兼容 10.1.x 版本的 `tomcat-embed-core/el/websocket`，不得残留 10.1.55。
- 若 10.1.59 与当前 Boot 3.5.16 产生真实不兼容，回退版本覆盖并保持 F06 开放，不以跳过测试或忽略扫描通过。

### D05 行数型重构关闭契约

- 第94条已经完成行为等价职责整改，第98条已关闭单纯千行告警；当前审计未提供新的调用冲突、事务冲突、重复权威或运行缺陷证据。
- 本轮不得抽取 `PayApplicationQueryService`、`PayApplicationWriteService` 或 `PayApplicationAssembler`；只删除失真的行数与固定拆分 TODO。
- F01 仍按现有服务边界最小修复；未来若出现新的具体职责冲突，必须以新证据重新过决策门，不在本计划制造候选。

## 6. 验收标准

### AC01 付款并发

- Mock/服务 0 行、H2 版本冲突和真实 loopback MySQL 并发均返回相同业务冲突语义。
- 两个同版本更新恰好 1 个成功；失败方不得生成成功响应或覆盖胜者；最终版本只递增一次。
- 来源校验失败时申请头、版本和来源全部回滚；既有草稿页面不得再分两次请求保存申请头与来源。
- 前端显示刷新重试提示并重新读取权威记录；普通更新、审批和金额口径回归不变。

### AC02 定时依赖复扫

- 定时 workflow 明确构建/解析当前 SHA JAR并调用与完整 CI 相同的产物扫描入口。
- 契约测试证明：既有源码 manifest 快扫保持独立；scheduled 与完整 CI 共同调用新的单一产物扫描入口，不再以“扫描源码 + 跳过 target”作为 backend rescan 完成条件。
- scheduled 的 JAR、库计数和扫描日志/报告绑定当前 SHA；完整 CI 的 SBOM 同样绑定该制品。缺产物、零运行时库、依赖解析告警、HIGH/CRITICAL 均为非零退出。

### AC03 模板和 MinIO

- 首装 `BOUND`、系统升级 `UPDATED_SYSTEM`、重复安装 `UNCHANGED_SYSTEM`、租户自定义 `PRESERVED_CUSTOM` 四态后端和前端测试全部通过。
- 只有真实绑定写入显示“系统默认已更新”；重复安装不再误报。
- `application-prod.yml` 注释与现有 `MinioHealthIndicator` 一致，运行时配置无语义差异。

### AC04 Tomcat

- `dependency:tree`、构建 JAR 和 SBOM 均证明 Tomcat 为 `10.1.59` 且无 10.1.55 残留。
- 后端全量、真实 MySQL、健康、文件、SSE 和付款关键链通过；制品 HIGH/CRITICAL 扫描通过。
- 本轮只形成本地安全维护结论，不声明生产可达性或上线条件。

### AC05 行数型重构关闭

- 不新增付款 Query/Write/Assembler 类，不拆散现有权威事务；F01 的根因修复保持现有路由、权限、租户、金额、状态机和查询预算，仅强化 PUT 写 DTO 与聚合事务。
- 失真 TODO 已删除；质量报告记录第94/98条既有裁决和本轮无新增职责冲突证据，F05 以“无新的可验收价值而关闭”收口。
