### 1.2 “不要旧数据”的判定

1. 独立新库初始化完成时业务事实表必须为空；不删除、不修改、不补写旧库现存记录。
2. 新记录的所有外键必须来自本轮 `01～15` 新对象台账。
3. 下拉候选出现旧记录时，只允许选择本轮已记录的新名称与回显 ID；找不到则该步骤 fail-close。
4. 新数据通过项目名称、业务主题、日期和回显 ID 形成独立集合，不使用“测试”“示例”“demo”“sample”等隔离词污染业务字段。
5. 验收时同时证明“新记录数量正确”和“未引用旧 ID”，不能只看页面总数增长。

### 1.3 非目标

- 不开发批量导入、种子数据、浏览器脚本、写接口或数据库脚本。
- 不新建 MySQL 容器或复制旧库；复用本地 MySQL 实例中的独立数据库和最小权限账号。
- 不修改业务规则、权限、自动编号、状态机、页面结构和既有数据。
- 不处理上线、部署、生产环境、真实账号、真实客户或真实个人信息。
- 不把查询、导出、刷新和状态动作伪装成“创建表单”计数。

### 1.4 风险

| 风险 | 处置与退出条件 |

| 回滚能力不足 | 只执行页面支持且可精确定位的删除/作废；无法安全回滚时停止后续写入 |

### 2.2 随机日期契约

1. 执行前冻结可编辑业务日期账本，保证合法因果和跨域自然日分布。
2. 用户可编辑业务日期总体分布在 `2026-01-01～2026-07-31`；项目计划完工日以服务端事实为准且不得早于同链合同、任务等合法下游最晚日期。服务端生成的创建、接收、提出和验收时间保持实际提交时间，不为满足统计口径反向篡改。
3. 每条链必须满足：
   - 项目立项 ≤ 合同签订 ≤ 合同生效 ≤ 计划开工 < 计划完工；

   - WBS计划开始 ≤ 日报日期 ≤ WBS计划完成；
   - 检查计划 ≤ 检查日期 ≤ 整改期限；
   - 计量期间结束 ≤ 结算日期 ≤ 付款申请日期；
   - 发票日期与付款、应收事实顺序符合对应业务规则。
4. 周末、月末、季度末和常规工作日混合分布；需要工作日约束的表单只选工作日。
5. 所有随机日期先写入执行账本再录表单，禁止边填边猜。

## 5. 浏览器实施规则

1. 只使用用户指定的内置浏览器和真实可见表单入口。
2. 不通过 `fetch`、控制台脚本、后端接口、SQL、migration或seed脚本创建数据。
3. 浏览器自动化只做与人工等价的点击、选择、填入和提交；每次提交后读取成功提示、列表或详情回显。
4. 自动编号字段保持只读，由服务端生成；外部发票号、报价号等业务字段按新日期账本生成且保持唯一。
5. 每次下拉选择必须用可见名称确认新对象，不手填数据库 ID。
6. 表单首次失败先分类；修复环境或输入后仅复验该条，不盲目重提。
7. 批次中断时记录最后成功的链号、表单、回显ID和下一步；恢复前先回读，防止重复创建。

## 7. 失败分类、暂停与恢复

- Docker、端口、数据库、前端代理、数据未加载：`environment_prerequisite`，恢复后复验。
- 浏览器参数、定位器或交互调用错误：`tool_invocation`，刷新页面状态后修正一次。
- 表单校验、权限、状态、金额、库存或日期契约失败：`quality_or_security`，不得绕过。
- 入口或证据未召回：`retrieval_gap`，使用允许的只读代码/图谱查证。
- 缺少合法上游对象或无法确定业务含义：`unknown`，暂停该表单并继续不依赖的链；不得引用旧数据填空。

## 8. 回滚

1. M1～M3金丝雀只保留草稿；确认下游可用后再执行提交/审批动作。
2. 草稿记录优先通过对应 UI 删除；删除前核对精确名称、链号和依赖。
3. 已进入状态机的记录只使用业务支持的撤回、作废、冲销或关闭动作，不直接删库。
4. 若某类表单无安全回滚入口，在首条金丝雀提交前暂停并记录为阻塞。
5. 禁止删除旧数据、删除命名卷、重置旧数据库或直接清理旧表；独立新库需废弃时另行确认精确目标和恢复边界。
