# 第60条主线：字典分组与三方一致性整改

**Goal:** 将字典管理升级为服务端事实驱动的“字典分组 → 字典类型 → 字典项”三级结构，收口现有分类漂移、管理权限、系统字典保护和业务写入校验。 **Architecture:** 新增租户级 `sys_dict_group`，`sys_dict_type` 关联分组并声明 `BUSINESS/SYSTEM/STATE_MACHINE` 分类；复用现有字典类型、字典项与权限体系，后端提供树形查询和统一启用值校验，前端只消费服务端层级，不硬编码分组或状态机允许值。禁止引入平行配置中心、前端权威分类、生产数据库操作或无关业务重构。

> 日期：2026-08-01
> 分支：`master`
> 状态：`COMPLETED / LOCAL_ONLY`
> 授权：本地代码、版本化 Flyway、测试、计划与浏览器验收
> 未授权：commit、push、PR、生产或生产数据库操作

## 范围与非目标

- 新增分组事实、分组 CRUD、类型归组、字典分类与三级只读树。
- 仅 `ADMIN/SUPER_ADMIN` 可管理分组、类型、字典项；服务端强制鉴权。
- `SYSTEM/STATE_MACHINE` 锁定类型编码和字典值；标签、颜色、排序及安全启停受控维护；状态机仍以后端状态机为权威。
- 盘点并修复 `pay_type`、结算状态、发票类型、费用类别、风险等级及前端硬编码消费漂移。
- 增加数据库、权限、保护、停用、消费与后端允许值三方一致性门禁。
- 非目标：重做状态机、删除历史字典、连接生产库、批量重构全部业务页面、Git 交付。

## 验收标准

- 至少形成系统治理、业务治理、项目、合同、供应链、结算、资金财务、工作流八个非空分组。
- `/system/dict/tree` 返回服务端层级；搜索可由分组、类型或字典项命中并带回父链。
- 页面默认只展开当前组，字典项每页 10 条且只有一个分页页脚。
- 非系统管理员写分组、类型、项均被服务端拒绝；前端权限控制只作交互补充。
- `SYSTEM/STATE_MACHINE` 的 `dict_code/dict_value` 不可修改或删除；停用不得绕过业务安全边界。
- `pay_type`、结算状态、发票、费用类别和风险等级形成迁移及契约证据；业务写入拒绝不存在或停用值。
- MySQL/H2 migration、相关后端测试、前端单测、类型检查、构建和浏览器验收通过。

| 前端层级或分页回归 | 服务端搜索、前端单一选中态和统一分页契约测试 | 回退为只读分组树，保留原 CRUD API |
