## 1. 结论与目标流程

当前实现顺序为：

```text
投标中标 → PREPARING项目 → 目标成本/预算/WBS → ACTIVE → 才允许创建主合同
```

目标顺序为：

```text
投标中标或直接审批立项
  → PREPARING项目
  → 已批准MAIN业主合同
  → 目标成本版本（主合同ID与金额快照）
  → 同源执行预算
  → 生效WBS基线
  → 开工准入审批及CLEAN证据
  → ACTIVE
```

`ACTIVE→COMPLETION→WARRANTY→CLOSED→ARCHIVED`继续由第68条既有施工与收尾状态机负责，本计划不重写后半程。

## 4. 核心业务契约

### 4.1 项目来源

| 来源 | 立项方式 | 必须证据 | 项目初始状态 |
| --- | --- | --- | --- |
| `BID_AWARD` | 复用第67条有效中标通知书幂等建项 | `source_bid_cost_id`、当前有效中标通知书、投标审计链 | `PREPARING / APPROVED` |
| `DIRECT_APPROVAL` | 复用既有`PROJECT_APPROVAL` | 项目审批实例与记录 | 审批通过后`PREPARING / APPROVED` |
| `LEGACY_UNCLASSIFIED` | 仅历史兼容 | G0预览与后续人工确认 | 保留现状；不得新进入`ACTIVE` |

新项目禁止空`initiation_basis`。历史项目不根据名称、金额或创建时间猜测来源。

### 4.2 金额权威

| 金额 | 唯一含义 | 使用边界 |
| --- | --- | --- |
| `bid_cost.final_bid_price` | 投标最终价/中标价事实 | 用于投标审计与价差比较，不是正式合同额 |
| 项目指定且已批准的`MAIN.current_amount` | 当前正式业主合同金额 | 目标成本新版本、经营分析和项目合同额投影的唯一来源 |
| `pm_project.contract_amount` | 正式主合同金额兼容投影 | 仅服务端随主合同批准/变更更新；客户端只读，不得独立修改 |
| `cost_target.source_contract_amount` | 目标成本版本合同额快照 | 历史冻结，不随主合同变更重算 |
| `cost_target.source_contract_id` | 目标成本版本来源主合同 | 新版本必填；必须等于项目指定合同，且租户、项目和合同类型一致 |

新建目标成本继续按`项目指定且已批准的MAIN.current_amount × 85%`计算。主合同后续批准变更时：更新项目兼容投影，但既有目标成本不重算；需调整时显式创建新目标成本版本，禁止后台静默改历史。

### 4.3 主合同阶段门

- `MAIN`合同：项目已批准且为`PREPARING`或`ACTIVE`时可维护；首次合同必须在`PREPARING`完成审批。
- `PURCHASE`、`SUBCONTRACT`等成本合同：继续要求`ACTIVE`项目与有效执行预算，不放宽现有门禁。
- 历史项目可保留多份`MAIN`合同，但每项目只能指定一份权威业主合同；新建目标成本和启用只认`pm_project.owner_contract_id`，不猜“最新一份”或汇总多份金额。
- 指定或改绑主合同必须锁定项目、校验同租户/同项目/`MAIN`类型；已有已批准目标成本后禁止改绑，例外只能走另行授权的数据修复。
- `MAIN`合同不占用项目成本预算、不生成锁定成本；现有合同审批、附件、金额拆分、税额重算和审计保持。
- 项目进入`ACTIVE`后，主合同总价不得直接编辑；金额变化继续走既有合同变更审批。

### 4.4 开工准入

新增最小`project_commencement`聚合，一项目一条：项目、拟/实际开工日期、开工依据类型、审批状态、审批实例、版本和审计字段。证据继续使用`sys_file`，业务类型为`PROJECT_COMMENCEMENT`，批准前至少存在一份`CLEAN`的`COMMENCEMENT_BASIS`附件。

不新增通用检查项表。提交和批准时动态复核既有事实：

1. 项目为`PREPARING / APPROVED`，来源为`BID_AWARD`或`DIRECT_APPROVAL`。
2. `owner_contract_id`指向同租户、同项目、已批准且履约中的`MAIN`合同。
3. 当前生效目标成本的`source_contract_id`指向该合同，金额快照等于创建该目标成本时的主合同当前金额。
4. 执行预算唯一、生效并来源于该目标成本。
5. WBS基线唯一、生效。
6. 开工依据附件扫描状态为`CLEAN`，开工日期合法。
7. 无跨租户、跨项目引用，无运行中的重复开工审批。

开工准入审批通过后，同一事务CAS执行`PREPARING→ACTIVE`、写入`actual_start_date`并回读全部来源、状态和金额。任何一步失败整体回滚。

### 4.5 实施前需要确认

| 决策 | 推荐默认值 | 未确认时处理 |
| --- | --- | --- |
| 中标是否等同项目审批通过 | 沿用第67条：有效中标直接生成`APPROVED / PREPARING`项目 | 不改中标建项状态 |
| 直接审批来源适用范围 | 仅非投标、直接委托和经确认的历史补录；新建必须走现有项目审批 | 禁止新增来源入口 |
| 中标价与签约价差异 | 允许差异并记录原因/预警，不阻断合同审批 | 只展示差异，不自动改金额 |
| 开工必需证据、确认角色及是否制单复核分离 | 一份`CLEAN`开工依据为技术最小值；具体文件清单和复核职责由业务负责人冻结 | 不提交开工准入审批 |
| 已`ACTIVE`项目的开工准入被撤销 | 禁止直接撤销；需暂停时走既有项目状态动作 | 保持状态并记录“需要确认” |
| 历史`ACTIVE`项目无权威主合同或开工事实 | 不降级、不伪造；首次恢复`ACTIVE`或新金额敏感写入前补齐 | 输出清单，禁止批量修复 |

以上默认值是计划建议，不是已确认业务事实。G1须将最终决策、责任人和日期写入实施质量报告；任何一项未决时，只能继续只读预览和契约设计。

## 5. 最小数据与接口变化

### 5.1 数据

- 扩展`pm_project.initiation_basis`约束：`BID_AWARD / DIRECT_APPROVAL / LEGACY_UNCLASSIFIED`。
- 新增`pm_project.owner_contract_id BIGINT NULL`；服务端校验同租户、同项目和`MAIN`类型，历史无法确定时保持空。
- 新增`cost_target.source_contract_id BIGINT NULL`；历史版本允许空，新版本必须指向项目指定主合同。
- 新增`project_commencement`及租户内项目唯一约束、审批实例/版本字段和复合外键。
- 不新增投标金额、项目金额或主合同金额表。

下一migration编号实施时从当前MySQL/H2最高`V273`继续前滚；不得修改已应用migration。

### 5.2 接口

- `GET /projects/{projectId}/activation-readiness`：返回来源、主合同、目标成本、预算、WBS、开工准入及阻塞项；全部服务端计算。
- `GET /projects/{projectId}/commencement`：读取开工准入单与审批状态。
- `POST /projects/{projectId}/commencement`：创建或保存草稿。
- `POST /projects/{projectId}/commencement/submit`：提交审批并重新校验前置。
- 现有项目详情返回只读正式合同额投影和中标价对照；前端不得提交权威合同额。
- 现有目标成本默认分配返回`sourceMainContractId`、合同编号、正式合同额和85%结果。

权限使用最小四项：`project:commencement:query/add/edit/submit`；管理员/超级管理员旁路沿用现有项目权限模型，所有服务仍执行项目数据范围与租户校验。

## 7. 服务端实施要点

1. 在一个共享服务中解析“项目指定且已批准的MAIN合同及当前金额”，供项目生命周期、目标成本和项目投影复用；禁止各模块复制查询口径。
2. `CtContractService`按合同类型分流项目阶段门；`MAIN`不走成本预算占用，其他合同现有门禁不变。
3. `ContractWorkflowHandler`批准`MAIN`时只同步项目金额投影并回读；合同变更批准后执行同一同步。不得重算历史目标成本。
4. `PmProjectService`拒绝客户端修改`contract_amount`和`initiation_basis`；直接审批通过时服务端写`DIRECT_APPROVAL`。
5. `BidAwardProjectService`继续幂等建项，但中标价只留在投标根；新项目合同额投影初始为0，等待正式主合同批准。
6. `CostTargetService`必须从共享主合同事实生成默认分配并写入合同ID/金额/85%快照；无合同、多合同、跨项目、金额漂移均fail-close。
7. `ProjectLifecycleService`集中计算准入结果；现有项目、目标成本和WBS审批回调即使重复触发，也只有全部条件和开工准入批准后才能CAS启用。
8. 开工审批处理器批准时再次锁定项目及来源事实；并发、重复回调和旧版本提交返回稳定错误或幂等回读。

## 8. 前端最小变化

- 项目详情新增“开工准入”卡，不新增独立平台；展示当前阶段、正式主合同、目标成本、预算、WBS、证据及阻塞跳转。
- `PREPARING`项目可从现有合同页创建`MAIN`合同；其他合同仍不显示可创建入口。
- 项目表单合同额改为服务端只读；中标来源项目单独展示“最终投标价”，避免标签混淆。
- 目标成本新建页显示来源主合同编号、正式金额、85%和10类明细；金额计算和保存裁决仍由服务端完成。
- 普通无权限角色隐藏开工操作且直达403；项目成员数据范围继续生效。
