## 3. 不变量

- 功能权限只决定能否调用功能；项目范围决定能操作哪些业务数据，两者不得互相替代。
- 指定无权项目返回 `PROJECT_ACCESS_DENIED`；未指定项目的列表只返回可访问项目，空范围返回空页。
- 项目范围必须进入 SQL 条件；禁止分页后内存过滤。
- 被拒绝的详情、删除和重提不得修改业务记录、订单预算占用或工作流状态。
- POM、Flyway 目录和实际 Git 状态是文档事实源；不长期保存无消费者的依赖树快照。

## 5. `ISSUE-063-001`：采购域项目数据范围授权收口

最小文件范围：

- `backend/src/main/java/com/cgcpms/purchase/service/MatPurchaseRequestService.java`
- `backend/src/main/java/com/cgcpms/purchase/service/MatPurchaseOrderService.java`
- `backend/src/main/java/com/cgcpms/receipt/service/MatReceiptService.java`
- 对应三个现有 Service 测试文件

实施要求：

1. 三个 `getPage()`：指定 `projectId` 先 `checkAccess`；未指定时用 `accessibleProjectIds()` 形成 SQL `IN`；空集合返回确定性空页。
2. 采购申请 `getById()`、`getItems()`、`delete()`、`resubmitForApproval()` 在租户、记录和工作流实例匹配后立即校验项目范围。
3. 采购订单、材料验收 `resubmitForApproval()` 在预算占用、工作流动作或审批状态更新前校验项目范围。
4. 检查三个服务全部 public 业务入口；保留已有正确门禁，不在 Controller 重复补丁，不改变 `ProjectAccessChecker`。
5. 覆盖 `ADMIN`、`SUPER_ADMIN`、`ALL`、`SELF`、项目经理、有效成员和“仅有功能权限、无项目关系”用户。
6. `SELF` 使用“本人创建项目允许、他人创建项目拒绝”的同租户双项目夹具。
7. 删除和三类重提拒绝后，回读业务记录、明细、订单预算占用及工作流状态，必须全部不变。

退出门：两项 P1 及同根重提路径失败关闭；授权项目和管理员行为无回归。
