# 第62条主线：采购执行优化整改与真实闭环

**Goal:** 在保留现有采购、合同、预算、库存、供应商退货、付款、文件、文档生成和工作流模块的前提下，修复当前采购执行优化差异中的迁移、审批数量、合同计价、验收、退货、付款来源及文档阻塞，形成“申请→审批→订单→验收→库存/直耗→退货/冲销→合同净应付→付款”的服务端权威、可审计闭环。 **Architecture:** 复用既有业务表、专用服务和正式 V2 页面；数量、金额、状态及来源占用只由服务端事务计算并在写后回读，不建立第二套采购、库存或应付账。优先修复共享根因和现有回归，禁止新增平行业务入口、客户端金额事实、通用工作流绕过、验收改价或无业务依据的历史数据猜测。

## 3. 范围与非目标

### 范围

- 采购申请、审批数量、审批审计、专用工作流入口和审批转单。
- 采购合同材料清单、FIXED/ACTUAL 计价、订单数量调整、预算审批轮次。
- 本次合格数量验收、系统批次、部分接收、库存/直耗、供应商退货及冲销。
- 合同净应付重算、MAT_RECEIPT 付款来源、累计占用和付款上限。
- 采购申请、采购订单与材料验收文档、默认模板、附件类型、权限、功能开关及前端操作。
- MySQL/H2 迁移、后端/前端自动化、mock E2E、真实 API/数据库和多角色浏览器验收。

### 非目标

- 一份申请拆分多供应商或多订单。
- 验收人员改价、同一订单不同到货批次临时改价。
- 删除历史质量处置字段或迁移历史质量业务。
- 第二套库存流水、采购应付账或前端平行计算。
- 生产发布、生产数据库、Git 交付和第61条主线收口。

## 4. 不变量与实施前置

- 数量、金额、价格来源、履约状态、净应付和付款可用额均以服务端事实为准；前端只提交命令并回读 VO。
- 采购申请原数量不可被审批覆盖；审批数量通过 CAS、任务归属、幂等键和变化审计原子更新。
- 固定价由合同清单强制覆盖；据实价来源可追溯，允许修改但必须由服务端重算金额。
- 验收只接受 `acceptedQuantity`；旧质量字段可读但不得进入新写模型。
- 合同净应付只能由已审批验收减有效合格品退货统一重算，不做增量手工修补。
- 付款必须同时受合同控制余额、合同净应付可用额和验收来源累计占用约束。
- 通用工作流对三类采购提交、重提及采购申请同意 fail-closed。
- 任何已应用 Flyway migration 禁止修改；是否允许修正当前未提交 V256～V258，必须先证明其未进入任何持久化共享环境。
- 实施前记录当前 HEAD、分支、完整 `git status --short`、第61条文件归属和采购差异清单；同文件修改只由主线程串行完成。

## 6. 阶段实施要求

### 6.1 基线与回归

1. 先修测试夹具与行为契约，不用放宽断言掩盖业务回归。
2. 为审批数量、合同净应付、付款上限、MAT_RECEIPT 来源、工作流绕过、采购文档 Provider 和迁移增加计划点名测试。
3. M5 Playwright 页面字段名与正式交互同步；mock 只证明前端契约，不替代真实后端证据。

### 6.2 迁移

1. 核查允许访问的 dev/test/demo `flyway_schema_history`；禁止连接生产。
2. 若证明 V256～V258 未进入任何持久化共享环境，可在首次正式采用前修正当前未提交 migration，并重建 checksum 证据。
3. 若任何持久化环境已经应用，立即冻结对应文件，设计版本化前向修复；不得改 checksum、手工伪造历史或跳过失败版本。
4. 增加双租户字典数据、复合外键、历史材料唯一/歧义/未匹配、净应付回填和 deleted_flag 场景。
5. 迁移遇到歧义材料映射必须停止并输出审计清单，不得任取第一条。

### 6.3 申请与订单

1. 申请写模型移除合同、预算、估价；历史查询保持兼容。
2. 审批命令包含任务、明细、审批数量、版本、原因及幂等键；服务端同事务完成 CAS、审计和工作流动作。
3. 工作台只对采购申请展示专用审批数量表单；其他业务仍走通用审批。
4. 订单选择合同后服务端确定供应商、计价模式和价格来源；固定价只读不是安全边界，服务端必须覆盖客户端值。
5. 预算预占幂等键包含 `budget_revision`；驳回/撤回释放后新轮次 CAS 增长。

### 6.4 验收、退货与付款

1. `POST /receipts/{id}/items/batch` 使用专用 DTO，拒绝 `actualQuantity`、`qualifiedQuantity`、`unqualifiedQuantity`、处置和手工批次字段。
2. 超收检查锁定订单明细，累计已收、退货、冲销和订单状态在同事务更新；重复回调不得重复入库、直耗或应付。
3. 退货冲销前校验加回后累计不超过订单数量，并重算履约状态。
4. MAT_RECEIPT 候选的退货额和付款占用分别聚合，禁止多表乘积；保存、提交、审批均重算净可用额。
5. 合同付款同时校验合同控制余额、净应付余额、验收来源净额和其他在途占用。

### 6.5 文档与附件

1. 验收页面分别上传 `DELIVERY_NOTE`、`MATERIAL_ACCEPTANCE_FORM`，显示缺失类型和扫描状态。
2. 发布《工程材料采购申请计划单》《采购订单》《工程材料到货验收单》的模板、版本与默认绑定。
3. Provider 使用服务端审批快照，覆盖项目、合同、供应商、申请/订单/验收明细、订单计价模式与价格来源、预算/WBS、审批记录、签字角色和附件字段目录；不接受客户端金额事实。
4. 采购申请和采购订单最终审批后在事务提交后生成正式文档；生成失败保留 `NOT_GENERATED/FAILED` 可审计状态，不回滚已成功审批。审批事件不负责创建采购订单。
5. 草稿/驳回采购订单允许带水印预览；订单详情复用现有生成、重试、历史、下载接口，打印通过正式 PDF 与浏览器/PDF 阅读器完成，不新增打印引擎。
6. 前端三类采购文档操作均复用现有文档接口；权限和功能开关由后端 fail-closed。

## 7. 恢复矩阵与渐进金丝雀

| 场景 | 停止条件 | 恢复方式 | 禁止项 |
| --- | --- | --- | --- |
| Migration 未应用 | 外键、主键、checksum 或历史映射预检失败 | 停止升级；修正未应用脚本后重建空库/旧库证据 | 跳版本、改 schema history、猜测材料映射 |
| Migration 已应用 | 发现持久化环境已有 V256～V258 | 冻结脚本；新增版本化前向修复并验证升级链 | 修改已应用文件、直接改业务金额 |
| 审批 CAS 冲突 | 版本、任务归属或幂等键不一致 | 返回明确冲突并重新读取服务端事实 | 覆盖原申请数量、客户端重试写入 |
| 订单/预算不一致 | 价格来源、固定价或预算轮次不一致 | 拒绝提交；回读合同和预算后重建草稿 | 前端金额兜底、复用旧轮次幂等键 |
| 验收/退货异常 | 超收、重复回调、冲销加回超量 | 事务回滚；按源单重算订单和净应付 | 手工改累计量、并行库存账 |
| 付款净额不明 | 退货、已付、在途占用无法一致计算 | fail-closed；统一重算后重新提交 | 仅按 current_amount 放款 |
| 文档失败 | 模板、Provider、存储或权限失败 | 保留失败状态和审计；授权用户重试 | 伪造成功记录、无附件放行 |

金丝雀顺序：静态与目标单测 → H2 active/legacy → 单租户 MySQL 空库 → 单租户旧库升级 → 双租户升级 → 单用户 API 主链 → 多角色浏览器主链 → 并发、退货/冲销、重复付款来源异常链。任一阶段首次不通过即停止扩大范围，先分类并修复根因。
