# 第84条主线：桌面窗口与三栏工作台视觉一致性整改

**Goal:** 统一 CGC-PMS 桌面窗口、全局工作区和三个高密度管理页面的视觉与交互契约：取消主内容蓝色外框、释放全宽工作区并在大屏渐进放大、将桌面应用限制为固定普通态或最大化态、把业务单据模板、用户管理、合作方管理改为单卡片三栏工作台。 **Architecture:** 继续复用 Win32 薄启动器、便携 Chromium、Vue 3 V2 应用壳、现有 `V2Card`、字典、服务接口、权限判断和编辑/确认弹窗；仅增加最小窗口样式控制、响应式令牌、主从选择状态和详情读取，不新增依赖、后端接口、数据库结构、权限或平行数据源，不处理尚未确认的工作区红色标签配色。

## 1. 范围、非目标与不变量

### 1.1 范围

1. 应用壳取消 `#shell-main-content` 自身蓝色焦点外框，保留路由后焦点转移、跳到主要内容和所有交互控件焦点提示。
2. 所有页面工作区取消 `90rem` 最大宽度，继续占满顶部栏以下高度；普通卡片随内容收口，工具型三栏卡片占满剩余高度。
3. 1920×1080 起整体渐进放大约 8%，2560×1440 起约 12%；使用响应式根字号/设计令牌，不使用 `zoom` 或 `transform: scale()`。
4. 桌面应用普通态固定居中 `1440×900` Windows 逻辑像素；允许移动、最小化、最大化、还原和关闭，禁止边框/角落拖拽缩放；小屏工作区不足时自动最大化。
5. 业务单据模板改为单工作台卡片内“业务模块 / 模板与版本 / HTML预览”三栏。
6. 用户管理改为单工作台卡片内“角色 / 用户 / 详情”三栏。
7. 客户管理统一业务术语为“合作方”，改为单工作台卡片内“类型 / 合作方 / 详情”三栏。

### 1.2 非目标

- 不改变工作区标签的红色配色；该项讨论未形成用户决定。
- 不新增或修改后端、数据库、Flyway migration、公开 API、权限码、角色、字典值、租户或业务状态机。
- 不把用户或合作方详情改为内联编辑；编辑、状态和删除继续使用既有权限判断、弹窗和确认流程。
- 不新增窗口状态持久化、自由尺寸、系统托盘、启动最大化配置或任意 Chromium 参数入口。
- 不修改独立合作方详情路由、模板渲染器、HTML 内容或用户/合作方权威数据来源。

### 1.3 不变量

- 主内容焦点仍在路由切换后更新；只移除主容器自身视觉轮廓。
- 1440×900 为窗口外框逻辑尺寸；最大化后还原必须返回该尺寸，每次启动不记忆上次状态。
- 三栏均使用语义 `section`、可见标题、键盘可选项和 `aria-selected`/`aria-pressed`；选中状态不得只依赖颜色。
- 用户和合作方详情必须由现有详情接口重新读取；角色/类型、筛选、分页、删除或状态变化后不得残留旧详情。
- 权限不足时原有新增、编辑、状态、删除、角色分配入口继续隐藏或禁用；当前账号禁止自我停用。

## 2. 实施设计

### 2.1 全局应用壳与大屏

- 将页面最大宽度令牌改为全宽，标题通知区与主内容使用同一可用宽度。
- 保持 1440×900 及更小视口现有基准密度；以宽高联合断点在 1920×1080 和 2560×1440 两档调整根字号到 108% 和 112%。
- 对 `.app-shell__content:focus` 和 `:focus-visible` 显式关闭主容器轮廓；按钮、链接、输入、菜单和表格行焦点样式不变。
- 更新应用壳 E2E：路由后主内容仍获得焦点，但其 `outline-style` 为 `none`；键盘跳过链接和控件焦点环仍存在。

### 2.2 桌面窗口

- 启动参数加入固定 `--window-size=1440,900`；不接受用户覆盖。
- Chromium 顶层窗口出现后等待初始化稳定，再以当前窗口 DPI 计算物理尺寸并施加 Win32 外框，避免浏览器启动参数在高 DPI 屏幕回写物理像素尺寸。
- Chromium 顶层应用窗口出现后，由启动器按 browser-root PID 和 `Chrome_WidgetWin_*` 顶层窗口特征定位，移除 `WS_THICKFRAME`，保留 `WS_SYSMENU`、`WS_MINIMIZEBOX`、`WS_MAXIMIZEBOX`。
- 普通屏幕将窗口按当前显示器工作区居中并设置 1440×900；工作区不足时调用最大化；样式变化后用 `SetWindowPos(...SWP_FRAMECHANGED)` 刷新非客户区。
- 启动器等待窗口采用有界超时；找不到窗口属于启动失败并记录脱敏分类，禁止静默放弃尺寸约束。
- fake Chromium 合同程序创建真实顶层窗口；契约构建在窗口配置完成后用测试专用窗口属性握手，避免替身提前最大化/还原形成竞态；验证启动参数、普通态尺寸、不可缩放样式、最大化/还原和小屏裁决；真实便携 Chromium 作为 G4 最终证据。

### 2.3 业务单据模板三栏

- 顶部标题/刷新/新增保留；下方三个独立 `V2Card` 合并为一个工作台 `V2Card`，内部三段 `section`。
- 三栏独立纵向滚动且标题固定；HTML `iframe` 保留自身文档滚动；桌面三栏比例延续现有 `0.6fr / 0.9fr / 1.5fr`。
- 小于既有 1180px 断点按业务模块、模板与版本、HTML预览改为单栏，并取消独立满高滚动。
- 模板、版本、分页、预览、编辑、发布、默认绑定、停用和权限行为不变。

### 2.4 用户管理三栏

- 在现有单卡片内将两栏扩展为“角色 / 用户 / 详情”；用户表改为紧凑可选列表，显示用户名、姓名、状态和既有更多操作。
- 新增 `selectedUserId`、详情加载/错误状态和请求版本隔离；当前页有数据时自动选择首位，无数据时清空并显示空状态。
- 详情栏只读展示用户名、姓名、联系方式、组织、角色、状态和创建时间；不放编辑、状态、删除或角色分配按钮。
- 编辑、状态、删除仍在用户栏原入口执行；成功后按服务端回读结果刷新当前列表与详情。
- 桌面栏宽为约 `0.65fr / 1fr / 0.8fr`，三栏独立滚动；980px 以下切为单栏页面滚动。

### 2.5 合作方管理三栏

- 类型栏使用服务端启用 `partner_type` 字典并提供“全部类型”；类型选择替代顶部重复的合作方类型下拉，编号、名称、状态筛选保留。
- 合作方栏改为紧凑可选列表，显示编号、名称、风险、状态和既有更多操作；不从当前页数据推导类型总数。
- 详情栏只读展示现有合作方详情字段；有数据时自动选中当前页首位，并用现有 `/partners/{id}` 回读权威详情。
- 编辑、状态、删除仍在合作方栏原入口执行；独立 `/partner/:id` 详情路由保留。
- 桌面三栏独立滚动；窄屏改为类型、合作方、详情单栏页面滚动。

## 5. 风险、失败分类与回滚

- **Chromium 窗口识别失败：** 有界等待后按 `environment_prerequisite` 或 `quality_or_security` 分类；不得以仅有启动参数冒充不可缩放验收。
- **DPI/小屏差异：** 使用每显示器 DPI 感知和工作区逻辑尺寸；无法容纳时只允许最大化，不裁切标题栏。
- **详情竞态：** 每个详情读取使用请求版本或 AbortController；旧响应不得覆盖新选择。
- **权限回归：** 权限不足、当前账号保护和服务端拒绝必须保持失败关闭；布局可见性不能扩大写权限。
- **嵌套滚动：** 三栏仅桌面独立滚动，窄屏恢复页面滚动；HTML iframe 的文档滚动是明确例外。
- **回滚：** 反向恢复第84条任务自有前端、桌面和测试补丁；无数据库、服务端或业务数据回滚。第82、83条既有提交不得因第84条回滚而丢失。
