# CGC-PMS v1.6 竞品情报与产品演进建议

**Goal:** 调查建筑工程总包项目管理同类产品，结合 CGC-PMS 当前真实能力，从功能与业务逻辑两层识别可复用优势、真实差距、优化顺序和后续开发方向。

**Architecture:** 保持“项目、合同、WBS、成本、采购、库存、分包、资金、文件和审批事实各自唯一”，新增能力优先引用、投影和下钻现有事实；不建设第二业务台账、第二财务账、通用低代码平台、独立原生移动端或无业务证据的 AI/BIM 平台。

## 2. 当前产品判断

CGC-PMS 已不是“模块缺失型”产品。现有优势是服务端权威业务链、租户与项目数据范围、金额和状态守恒、文件证据、审批、审计及 Trace：

```text
投标/直接立项
  -> PREPARING
  -> 已批准 MAIN 合同
  -> 目标成本 + 执行预算 + WBS + 开工准入
  -> ACTIVE 施工履约
  -> 合同/变更/采购/库存/分包/产值
  -> 申请/审批/收付款/发票/凭证/月结
  -> 收尾/质保/关闭/归档
```

已交付且不应重复建设：

- 项目、合同、目标成本、预算、WBS、施工日报、质量安全、技术图纸/RFI、竣工收尾。
- 采购申请、询价招标、报价评审、定标、订单、验收、库存、领退料、供应商退货、履约评价、黑名单。
- 分包任务、计量、结算、付款；收入、回款、发票、现金日记账、资金预测、凭证和月结。
- 可关闭预警、SLA 升级、规则效果复盘、站内通知、项目文件中心、受控 Office/PDF、业务单据模板。
- PWA 现场日报与质量安全最小闭环；RBAC、租户隔离、项目范围、审计和业务 Trace。

当前真实短板不是再增加同名模块，而是：

1. WBS 仅有 P0 计划能力；多前置 FS 尚未进入 Ready，其他依赖类型、工作日历、关键路径和资源负荷仍是更后期方向。
2. 采购与库存 P0 已闭环，且已支持累计占量和部分到货；批次质保、延期/缺货履约分析、库存预留、盘点调整和可解释补货仍待深化。
3. 现场人员、设备、天气、定位、深度离线等没有单一已证价值链。
4. 图纸/RFI 已闭环，Submittal、受控分发签收、在线批注和外部设计协同仍缺真实样本。
5. 角色驾驶舱和同步报表已存在，组合项目经营、统一口径下钻和大数据量报表尚未证明必要性。
6. 外部渠道、门户、P6/MS Project、BIM/IFC、外部财务和开放生态均缺首个确定目标及安全前置。

## 6. 详细优化方向

### O1. 采购补货决策金丝雀（近期优先，复用 `A-02`）

- 功能：选择一个物料/项目场景，给出建议日期、建议数量、来源明细和解释；不自动创建采购订单。
- 逻辑：先确定唯一工作日历、需求对象和提前期来源；历史净领料只作历史事实，已批准未来需求才可进入确定性投影。
- 不变量：租户/项目范围正确；单位换算明确；建议可回放；人工确认后仍走既有采购审批和预算门。
- Ready 前置：真实样本、基线误差、可接受误差、业务收益、权限和回滚均明确。
- 验收：每条建议 100% 可追到库存、在途、已批准需求和提前期；重复计算结果稳定；无自动金额或库存写入。

### O2. 复杂计划演进（战略方向，首切片复用 `A-04`）

- 首切片：只增加多前置 FS，保留现有基线、审批、进度快照和纠偏模型。
- 首切片不包含：SS/FF/SF、提前/滞后量、工作日历、关键路径、资源平衡、自动排程或外部集成；完成首切片并取得新证据后再逐项决策。
- 逻辑：任务依赖必须同项目、无环；所有前置任务满足后才允许推进；已批准基线不可覆盖；实际进度继续来自日报/履约事实。
- 复用：现有 `ProjectScheduleService`、审批、进度快照、纠偏、预警和 Trace；不新建第二计划平台。
- Ready 前置：至少一个当前单前置模型无法表达、但多前置 FS 足以表达的项目样本和预期依赖集合。
- 验收：重复边拒绝、环检测失败关闭、跨项目依赖拒绝、基线可重放；任一前置未完成时状态推进被服务端阻断。

### O3. 材料现场执行深化（近期，复用采购/库存业务标准）

- 功能优先顺序：订单延期/缺货履约分析、材料批次/炉批/质保复检、库存预留、盘点调整；扫码/OCR 后置。现有部分到货继续复用，不重复建设。
- 逻辑：订单行剩余量、到货量、合格量、退货量、入库量、预留量和可用量守恒；任何调整都需审批、原因和审计。
- 复用：现有订单、验收、库存流水、领退料、文件安全和供应商评价。
- 验收：超收或其他数量越界默认拒绝，本方向不引入超收例外流程；库存不为负；同一验收幂等；批次附件为 CLEAN；成本只在权威节点生成一次。

### O4. 现有闭环的可见性与例外管理（低风险优化）

- 功能：下游页面展示来源签证/合同/预算/WBS；索赔时限待办；变更卷宗导出；计划、材料、资金异常统一跳转到原业务对象。
- 逻辑：驾驶舱和预警仅聚合，不产生第二事实；每个指标保留口径、来源、时间和权限。
- 去重：不新增 Change Event、风险台账或手工汇总表；现有 RFI、签证、预警和 Trace 能承接时直接复用。
- 验收：来源链无孤儿、无双计；聚合值等于授权范围内源事实；任何异常可下钻到责任人、截止日和关闭证据。

### O5. 组合项目经营与预测（中期，复用 `A-06`）

- 功能：企业/项目两级的进度、成本、动态利润、现金缺口、重大风险和关闭状态；项目下钻而非只看大屏。
- 逻辑：施工方经营口径与建设方投资口径分离；组合值只汇总用户可见项目；历史快照不可被当前状态改写。
- 最小切片：先选一个明确报表，例如“项目群进度—成本—现金风险清单”，证明同步路径不够后才考虑异步任务。
- 验收：每个 KPI 有公式、来源、分母、时间点和不可用语义；项目合计与组合汇总一致；越权项目数量和金额均不可推断。

### O6. 时间—资源—成本联动（中期，依赖 O2/O3）

- 功能：WBS 任务关联材料需求、班组/设备计划、分包任务、产值和成本；显示计划、实际、剩余和完工预测。
- 逻辑：先建立映射，不复制源数据；人员、设备、材料实绩分别来自其权威业务对象；缺失事实显示不可用，不按 0 处理。
- 边界：不在首版建设工资、设备租赁或 IoT 平台；先选材料或一个班组场景。
- 验收：同一事实不重复归集；版本变化可追溯；资源不足只产生建议/预警，不自动改计划或合同。

### O7. Submittal 与受控技术协同（中期，复用 `A-09`）

- 功能：材料/设备报审台账、提交包版本、专业复核、退回重提、批准发布、现场签收和归档。
- 逻辑：必须绑定项目、合同/材料、图纸版本和文件版本；批准版本不可覆盖；旧版保留但不可继续用于施工。
- 复用：现有图纸、RFI、技术方案、工作流、文件中心、单据模板和项目关闭门。
- 验收：职责分离；状态迁移服务端校验；附件安全；批准/作废/替代关系完整；无真实样本则保持 Frozen。

### O8. 外部协作与深度移动（后期，复用 `A-03/A-07/A-10`）

- 功能顺序：单一真实通知渠道；供应商/业主/设计方受限任务门户；单一离线现场表单；二维码或定位证据。
- 逻辑：外部参与者只可处理被分配对象；内部成本、其他项目和敏感附件默认不可见；离线写入带幂等键、设备时间、服务端时间和冲突状态。
- 边界：不新建全量外部后台，不把发送成功等同业务送达，不允许离线端直接覆盖结算、库存或审批终态。
- 验收：撤权即时生效；重放无重复事实；同步冲突可见；通知请求、渠道回执和业务确认分层记录。

### O9. 开放集成与 BIM（长期，复用 `A-10`）

- 集成：先单向导入 P6/MS Project 或一个外部财务接口；契约、数据所有权、对账、重试和回滚先于双向同步。
- BIM：先做 `WBS/图纸版本/质量问题 -> 构件` 定位；没有稳定映射前不做 4D、数字孪生或模型驱动计量。
- 通用 AI：受控文档检索、Trace 摘要、字段建议和异常解释均因缺少单一用户场景、评测集和正式载体而关闭，不纳入本路线。未来若出现领域内真实样本，重新过决策门，并禁止自动审批、自动定标或修改合同、预算、付款。

## 7. 推荐开发顺序

时间窗口只表示依赖顺序，不构成版本或交付承诺。各阶段“目标”均为候选池，不是并行实施清单；每次最多选择一个完成取证、进入 Ready 且另获授权的最小业务链，其余保持原状态。每个被选方向仍需独立 G0～G5 计划。

| 阶段 | 建议周期 | 目标 | 进入条件 | 退出条件 |
| --- | --- | --- | --- | --- |
| D0 取证与裁决 | 0～4 周 | 仅为拟评审的一个方向取得真实样本和基线指标 | 明确角色、痛点、频次、源数据 | 最多形成一个最小 Ready；其余保持原状态，只有取得关闭证据的方向才关闭 |
| D1 近期优化 | 1～3 月 | 候选池：O1，或 O3 中一个材料闭环，或 O4 中一个来源可见性闭环 | 被选方向已在 D0 证明价值并进入 Ready | 被选闭环的来源、权限、数量、金额、幂等和回滚通过 |
| D2 项目控制深化 | 3～6 月 | 候选池：O2 多前置 FS，或 O5 一个组合经营报表 | 被选方向的项目/报表样本成立并单独进入 Ready | 被选闭环的依赖守卫/基线或组合口径/下钻通过 |
| D3 协同与资源 | 6～12 月 | 候选池：O6 单一资源场景，或 O7 Submittal，或 O8 一个门户/离线场景 | 被选方向事实稳定，身份/安全边界清晰并单独进入 Ready | 被选闭环无双录、无越权、无静默冲突，审计完整 |
| D4 生态连接 | 12 月后 | 候选池：O9 单一外部集成，或 BIM 定位 | 被选接口/模型有数据所有权和量化收益并单独进入 Ready | 被选闭环可对账、可回放、可回滚；无双向失控写入 |

## 8. 产品指标

先建立当前基线，再设目标值；不得复制厂商宣传数据。

| 指标 | 定义 |
| --- | --- |
| 来源关联完整率 | 应关联业务记录中，可追到权威来源版本的比例 |
| 一次录入率 | 下游复用源事实而无需重复录入的记录比例 |
| 守恒差异数 | 数量、金额、库存、预算、应收应付和总账不一致数量 |
| 异常闭环时长 | 预警创建至接单、处理、归档的分位时长 |
| 计划预测偏差 | 基线/最新预测与真实完成日期、进度的差异 |
| 材料决策质量 | 缺料、超储、异常损耗及建议被采纳后的回放结果 |
| 组合口径可追溯率 | 组合 KPI 可下钻到项目和源单据的比例 |
| 移动同步可靠性 | 重复、丢失、冲突、人工修复和最终一致数量 |

## 9. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 复制竞品模块导致重复台账 | 先查现有对象和调用链；优先映射、投影、下钻和删除重复入口 |
| 计划平台一次做大 | 首切片只做多前置 FS；工作日历、关键路径、资源平衡和外部集成分别另行决策 |
| 预测伪精确 | 区分历史事实、确定性未来量和统计预测；无评测集只给规则建议 |
| 门户/移动越权 | 最小权限、项目范围、受限对象、撤权、幂等和冲突审计 |
| BIM 成为展示工程 | 必须绑定业务对象、用户决策和量化指标；否则关闭候选 |
| 报表成为第二事实 | 报表只读投影；口径、来源和不可用语义显式化 |
| 历史数据被猜测回填 | 证据不足标记不可用；不反推审批、附件、版本或金额事实 |

## 10. 裁决

1. 核心定位保持“建筑总包项目经营与履约控制平台”，不转为通用 ERP、BIM 平台或低代码平台。
2. 近期最可落地方向是 `A-02` 的可解释补货金丝雀；战略价值最高方向是 `A-04` 的多前置 FS 首切片。工作日历、关键路径和资源平衡须在首切片后另行决策。
3. 供应商评价、RFI、预警、资金预测、PWA 日报均已存在；相关“新增模块”建议关闭，后续只做有证据的深化。
4. 组合经营、Submittal、外部门户和深度移动进入中期候选；BIM、P6/MS Project 和概率预测保持长期方向。通用只读 AI 因无单一场景、评测集和正式载体而关闭，未来有新证据时重新决策。
5. 正式后续项新增 0、关闭 0、净变化 0。“新增供应商评价、RFI、风险台账、现金预测台账、原生移动端、通用只读 AI”六类仅为本轮发现的重复或证据不足提议，不是既有或新建正式后续项；前五类已有能力承接，AI 类无可验收价值，均关闭且不计入后续项增减。保留建议由既有 `A-02/A-03/A-04/A-06/A-07/A-09/A-10` 或现行业务标准承接；无无载体遗留项。
