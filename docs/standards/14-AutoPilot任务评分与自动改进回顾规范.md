# AutoPilot 任务评分与自动改进回顾规范

## 1. 适用范围与权威

本规范只保存稳定业务语义。评分是通过任务的观测数据，不是质量门禁，不能替代测试、权限、安全、数据一致性、范围或零悬空裁决。

当前激活版本、批准状态、权重、生效点、回顾阈值、模型、并行度和超时只读取：

- [控制面策略](../../plugins/cgc-pms-autopilot/references/control-plane-policy.md)
- `scripts/codex-autopilot/codex-autopilot.config.json`
- `plugins/cgc-pms-autopilot/schemas/**`
- 配置引用的批准来源

本规范不得复制这些动态值；历史版本事实只保留在对应批准记录和归档报告。

## 2. 批准与版本不变量

- 候选版本与活动版本分离；未获明确批准时只能校验和回放，不写正式评分或回顾计数。
- 评分绑定原版本，不重算或覆盖历史；一个任务只允许一个正式版本和一个回顾周期计数。
- 配置、Schema 与批准来源不一致时 fail-close。

## 3. 两阶段收口

只有全部硬门禁通过并完成正式证据归档的实施型 Ready Issue 才能评分：

1. `implementationCommit` 冻结实现与证据。
2. 评分器从该提交的结构化证据确定性计算，并生成稳定幂等键。
3. 独立 `closeoutCommit` 写入评分和 Done/backlog 收口事实。
4. closeout ledger 写后读回成功后，才加入回顾周期。

缺失证据、硬门禁失败或两阶段收口未完成时拒绝评分。低分不改变 DONE 裁决，也不自动触发补修或回滚。

## 4. 回顾与恢复

- 回顾按 Issue ID 和评分键去重，跨批次累计；何时触发只读取动态配置。
- 回顾聚合总分、维度分布、首次通过率、阶段耗时、重复根因、后续项净变化和存量问题变化；单个低分不得自动立项。
- 提案必须具备稳定键、证据、价值、最小方案、非目标、依赖、回滚和验收，并以 `NEEDS_CONFIRMATION` 去重写入唯一问题事实源。
- 报告、Ready 历史、问题事实、知识图谱游标和稳定 Episode 未全部写后读回时，不得清零；失败从最后确认阶段幂等恢复。

## 5. 安全与证据边界

- 不连接或发布生产，不自动 push，不因效率评分裁剪必需验证。
- checkpoint 是可丢弃运行态；正式报告只存聚合指标和失败分类，不保存 run id、PID、原始日志或临时路径。
- 效率证据区分业务实施与控制面/工具恢复成本；固定时长不直接决定业务质量。
- 同一 Ready 内容和执行基线不得重复派发 implementation；恢复复用原实现提交与评分幂等键。
