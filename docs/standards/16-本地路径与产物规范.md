# 本地路径与产物规范

状态：Active
适用范围：CGC-PMS Windows 本地开发、诊断、验证与自动化产物。本文不授权迁移、删除、Git 发布或非本地环境操作。
审计只读，不自动迁移、不自动删除。

## 路径矩阵

| 用途 | 规范路径 | Owner | 命名与边界 | 保留/清理规则 |
| --- | --- | --- | --- | --- |
| 主仓 | `D:\projects-test\cgc-pms` | 项目维护者 | 固定路径；持续保留 | 不作为临时目录清理，不因另建 clone/worktree 迁移或替换 |
| 临时 clone | `D:\projects-test\_clones\cgc-pms\<purpose>-<yyyyMMdd-HHmmss>` | 创建者 | 一项临时任务一个目录；时间戳使用本地创建时间；不得与主仓同名同级混放 | 任务结束后仅在证明无未提交、未推送或需留存成果时清理 |
| 人工 worktree | `D:\projects-test\_worktrees\cgc-pms\<branch-slug>` | 创建者及分支负责人 | 目录名对应分支；同一分支不得重复建树 | 仅在分支已合并或明确废弃、无未推送提交、无未提交成果、无占用时清理 |
| AutoPilot worktree 例外 | `D:\projects-test\cgc-pms\.worktrees\autopilot\<issue-id>` | AutoPilot Owner | 仅 AutoPilot 控制面按其规范创建；不得推广为人工 worktree 路径 | 按 AutoPilot checkpoint、fencing、恢复与清理证据执行；证据缺失时隔离保留 |

| 备份 | `D:\backups\cgc-pms\<category>` | 数据/服务负责人 | 类别至少为 `mysql`、`minio`、`data-maintenance`、`git-bundle`、`snapshots`、`quarantine`；文件沿用各工具时间戳命名 | 按备份策略保留；清理前确认恢复点、校验结果、保留窗口与替代副本 |

| 临时文件 | `%TEMP%\cgc-pms\<task-id>` | 创建任务或进程 | 每任务隔离；不得存唯一成果、密钥或长期证据 | 任务完成且成果已转存、无进程占用后可清理 |
| 构建与测试产物 | 模块内 `target/`、`dist/`、`out/`、`coverage/`、`test-results/` | 构建或测试任务 | 保持工具默认模块内路径；属于规范例外，不迁往共享缓存或 `D:\var` | 可重建不等于可直接删除；确认无进程占用、无验收取证需要后按任务清理 |
| 桌面启动器数据 | `%LOCALAPPDATA%\CGC-PMS\Desktop` | 桌面启动器维护者及当前 Windows 用户 | 启动器缓存、Chromium、profile、状态和日志专属路径；属于规范例外 | 按桌面启动器手册清理；profile 删除会清除登录态与未同步本地草稿 |
| Docker 依赖缓存 | Compose 命名卷 `maven-repo`、`pnpm-store` | Compose/Docker 运行态负责人 | 由 Docker 管理实际路径；属于共享缓存根之外的规范例外 | 不直接操作 Docker 卷内部文件；清理前证明无运行容器依赖且可重新获取依赖 |
| 仓内运行证据例外 | `.agent-runtime/`、`.codex-autopilot/`、`local-evidence/` | 对应任务或控制面 Owner | 仅存本地运行、控制面和持久证据；不得提交敏感运行态 | 服从专项证据、checkpoint 与恢复规则；证据归属不明时保留并报告 |

`<purpose>`、`<branch-slug>`、`<tool-or-purpose>`、`<component>` 和 `<task-id>` 使用小写 ASCII、数字与短横线；名称必须能追溯到任务、分支、工具或组件。路径中不得写入真实密钥、Token 或个人敏感信息。

## 主仓根目录白名单

主仓根目录只允许以下入口；新增未列出的顶层文件或目录属于 `FORBIDDEN_NEW`：

| 类别 | 允许入口 |
| --- | --- |
| 产品模块 | `backend/`、`frontend-admin-v2/`、`desktop-launcher/`、`packages/` |
| 工程能力 | `deploy/`、`scripts/`、`tools/`、`plugins/` |
| 文档与历史 | `docs/`、冻结且只读的 `archive/` |
| 控制目录 | `.git/`、`.github/`、`.agents/`、`.codex/`、`.githooks/` |
| 本地运行态例外 | `.worktrees/`、`.agent-runtime/`、`.codex-autopilot/`、`.codegraph/`、`local-evidence/` |
| 根文件 | `.gitattributes`、`.gitignore`、`AGENTS.md`、`CHANGELOG.md`、`README.md`、`skills-lock.json` |

审计结果 `COMPLIANT` 只表示受检路径的布局和命名符合本规范，不证明内容无价值、可重建、无人占用或已获删除授权。任何移动或删除仍须满足本规范的保留、恢复和授权门槛。

已知根目录遗留按以下目标收口，不把它们加入白名单：

| 遗留入口 | 处理目标 |
| --- | --- |
| `design-qa.md` | 移入 `docs/archive/v1.5/quality/`，同步修正仍承担稳定锚点的引用 |
| `output/` | 正式引用证据迁入 `local-evidence/`；其余内容逐项取证后清理 |
| `memory/` | 有长期价值的项目记录迁入 `docs/quality/`；其余本地笔记整体外置，保护内容不扫描 |
| `mobile/` | 仅占位且无实现时删除；出现真实移动端实现后再按产品模块变更白名单 |
| `frontend-admin/` | 保护内容按授权整体隔离至 `quarantine` 后删除遗留空壳，不扫描保护内容 |

## 产物保留与清理证据

- 四类处理：活跃依赖/缓存默认保留；可离线复用冷缓存按版本或期限保留；正式证据脱敏归档；仅损坏或无调用方产物进入清理候选。命中 `.gitignore`、可重建或可下载不能单独证明应删除。
- 依赖树进入清理候选前，必须核实调用方、lockfile、实际 `storeDir`，并在一次性目录完成离线安装；失败即保留缓存或补齐缺包，禁止联网重下冒充验证。
- `.codegraph` 等索引的新鲜度必须联合核对数据库文件、守护日志、进程或锁及补同步结果；父目录时间不得单独触发删除或重建。
- 清理记录至少包含：精确路径、Owner、用途、创建/最后使用依据、Git 或进程占用检查、需保留成果的转存位置、恢复方式、执行人与时间、清理后不存在性验证。破坏性操作仍须服从 `AGENTS.md` 授权门禁。

## 遗留路径与保护目录

- 发现不符合矩阵的既有 clone、worktree、缓存、备份、日志或数据时，只报告精确路径、推定用途、Owner/归属证据和建议目标；不得自动移动、重命名、合并或删除。迁移必须另获明确授权并先给出冲突、占用、回滚和验证方案。
- 禁止在 `D:\` 根目录或 `D:\projects-test\` 中与主仓同级新增散落 clone、cache 或 backup；必须使用矩阵指定根目录。发现既有散落目录仍按遗留路径规则只报告，不自动迁移。
- 默认禁止读取、扫描、修改、总结或清理 `.omc/`、`.omo/`、`.opencode/`、`.claude/`、`.mimocode/`、`graphify-out/`、`.sisyphus/`、`.archive/`、`archive/v1.0/private/`。只有用户点名并明确解除禁止后方可处理。
- 路径矩阵不改变仓库内 `.gitignore`、工具自身生命周期或专项 Skill 的更严格门禁；发生冲突时采用更严格规则。
