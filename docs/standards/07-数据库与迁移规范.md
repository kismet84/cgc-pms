# 07 数据库与迁移规范

> 适用版本：v1.6。历史结论和旧路径仅作回溯，当前实现以本分支代码、配置和实时验证为准。

## 角色入口

主负责人：数据库与迁移负责人。补充阅读：[09 测试规范](09-测试规范.md)。任何数据库结构变化必须新增版本化 migration，不修改已应用脚本。

## 环境与基线

| 环境 | 数据库 | 当前迁移入口 |
| --- | --- | --- |
| dev / prod | MySQL 8.0 | `backend/src/main/resources/db/migration/` |
| local / test | H2 MySQL 模式 | `backend/src/main/resources/db/migration-h2/` |
| 既有库历史兼容 | MySQL / H2 | 对应 `*-legacy/` 与既有 Java migration |

当前最终基线为 B215。新环境从 B215 启动；既有库继续扫描 legacy 并通过 validation。详细边界见 [数据库最终基线 B215](../database/database-baseline-v215.md)。

## Flyway 规则

1. 已执行的 `V*.sql` 不得修改；结构或数据修复新增 `V{next}__description.sql`。
2. MySQL 与 H2 差异较大时分别维护，并由迁移行为测试证明语义一致。
3. 文件使用 UTF-8；生产保持 `validate-on-migrate=true`。
4. 使用 `scripts/check-flyway-immutability.sh` 或 `.bat` 检查已提交 migration 不可变性。
5. 不以恢复旧脚本、关闭 validation 或修改已应用 checksum 代替新增迁移。

## 主键、审计与类型

```sql
id BIGINT NOT NULL PRIMARY KEY
```

通用审计字段按表需要使用 `tenant_id`、`created_by/at`、`updated_by/at`、`deleted_flag`、`remark`。金额使用 `DECIMAL(18,2)`，状态/类型使用稳定字符串码，长文本使用 `TEXT`，结构化 JSON 使用 MySQL 8 `JSON`。

## 逻辑删除与活动行唯一性

`deleted_flag` 是逻辑删除事实。需要“活动行唯一、删除后可重建”的业务键使用生成列：

```sql
active_unique_token BIGINT GENERATED ALWAYS AS
  (CASE WHEN deleted_flag = 0 THEN 0 ELSE id END) STORED,
UNIQUE KEY uk_tenant_code (tenant_id, code, active_unique_token)
```

活动行 token 固定为 `0`，相同业务键只能存在一条；删除行 token 为自身 `id`，可保留历史并重建同业务键。B215 MySQL/H2 基线、V210 legacy 退役迁移及 `MigrationSoftDeleteBehaviorTest`、`MigrationIntegrityTest` 是当前验证入口。

`deleted_token` 属于已退役 legacy 兼容方案，不得恢复为当前设计。历史 V88/V210 只供迁移链回溯，不修改原文件迎合当前规范。

## 索引规范

| 场景 | 建议索引 |
| --- | --- |
| 租户查询 | `(tenant_id)` 或组合业务键 |
| 项目列表 | `(tenant_id, project_id)` |
| 合同业务 | `(tenant_id, contract_id)` |
| 审批任务 | `(tenant_id, approver_id, task_status)` |
| 来源幂等 | `(tenant_id, source_type, source_id)` |

不盲目增加单列索引；高频列表查询必须有匹配索引。

## 禁止事项

1. 生产手工改表不补 migration。
2. 修改已执行 migration 或绕过 validation。
3. 使用浮点数存金额。
4. 无 WHERE 条件批量 update/delete。
5. 绕过租户或项目范围全表查询。
