# 05 前端开发规范

> 适用版本：v1.6。历史结论和旧路径仅作回溯，当前实现以本分支代码、配置和实时验证为准。

## 角色入口

主负责人：前端设计师 / 前端架构助手。补充阅读：[00 UI 设计基线](00-UI-Design-Baselines-and-Code-Specifications.md)、[09 测试规范](09-测试规范.md)。

## 技术栈

Vue 3.5、TypeScript 5.6、Vite 6、Pinia、Vue Router、原生 Fetch，以及 `@cgc-pms/frontend-contracts` 共享契约。

UI 使用 `src/components/index.ts` 导出的 V2 组件和 `--v2-*` token。不引入第二套 UI 组件库或状态管理方案，除非有明确迁移计划。

## 目录职责

| 目录 | 职责 |
|------|------|
| `src/pages/<module>/` | 页面与页面私有组件 |
| `src/pages/<module>/application/` | 复杂页面的私有用例编排与端口定义 |
| `src/pages/<module>/infrastructure/` | 实现上述端口的页面私有浏览器适配器 |
| `src/services/<module>.ts` | 模块 API 封装 |
| `../packages/frontend-contracts/` | 共享接口类型、API 路径与枚举 |
| `src/router.ts` | 路由定义、守卫、页面标题 |
| `src/navigation/catalog.ts` | 导航菜单业务域、顺序与权限 |
| `src/stores/` | 跨页面共享状态 |
| `src/components/` | 共享组件 |

页面私有逻辑留在页面目录，不用过早提升。仅当页面同时混合 UI、用例编排和浏览器持久化时，才按 `application/` 与 `infrastructure/` 拆分；页面作为组合点，应用层不得导入 Vue、Router 或全局 `window`。

## TypeScript 规范

1. API 返回值必须声明泛型类型
2. 后端 ID 统一为 `string`（不用 `number`）
3. 金额统一为 `string`，展示时格式化
4. 枚举集中定义，不在页面硬编码
5. 禁止 `any` 绕过接口契约

```ts
interface CostTargetVO {
  id: string
  projectId: string
  versionNo: string
  totalTargetAmount: string
  approvalStatus: 'DRAFT' | 'APPROVING' | 'APPROVED' | 'REJECTED'
}
```

## API 调用规范

1. 页面通过 `src/services/` 的领域函数调用 API，不直接调用 `fetch`
2. 领域服务 URL 不写 `/api` 前缀，由 `src/services/request.ts` 统一添加
3. 删除、提交、审批等操作必须有确认交互和加载态
4. 异常交给统一请求生命周期提示；页面仍须在 `finally` 恢复加载态

```ts
import { deleteInvoice } from '@/services/finance'

const handleDelete = async (id: string) => {
  try {
    await deleteInvoice(id)
    await fetchList()
  } finally {
    deleting.value = false
  }
}
```

## 页面状态模式

| 状态 | 用途 |
|------|------|
| `loading` | 列表首次加载 |
| `saving` | 保存中 |
| `submitting` | 提交审批中 |
| `deleting` | 删除中 |
| `query` | 查询条件 |
| `tableData` | 表格数据 |
| `pagination` | 分页 `{pageNo, pageSize, total}` |

规则：
- 加载态在 `finally` 中恢复
- 删除成功后刷新；当前页为空可回退一页
- 按钮由后端权限和业务状态控制，不以静态角色判断

## UI 与样式

唯一规范：[CGC-PMS 唯一设计系统标准与门禁](00-UI-Design-Baselines-and-Code-Specifications.md)。

- `frontend-admin-v2`：唯一现行前端，只使用 `--v2-*` token 和 `src/components/index.ts` 公开组件，页面不得定义第二套公共材质。
- `archive/v1.6/frontend-admin-legacy`：Legacy 只读归档，不得被新代码导入或作为新标准。
- 禁止从归档复制 UI 组件、样式和 DOM 适配层。
- 表格、表单、弹窗、状态、响应式、无障碍、视觉预览及交付命令全部以唯一规范和其自动门禁为准。

## 表单规范

1. 必填项前端后端双重校验
2. 日期使用后端约定格式
3. 金额保留两位精度，提交为字符串
4. 下拉字典来自字典接口/store，不硬编码中文标签
5. 编辑页加载失败需给出提示并可重试

## 权限规范

1. 菜单权限来自后端用户信息 + 路由配置
2. 按钮权限以后端 `availableActions` 或接口返回为准
3. 前端隐藏按钮只是体验优化，后端强制拦截

## 测试

```powershell
pnpm --dir frontend-admin-v2 build
pnpm --dir frontend-admin-v2 test:unit
pnpm --dir frontend-admin-v2 test:e2e:contract
```

高风险页面需覆盖：登录与权限、审批流转、删除/保存/刷新、表单校验、ID/金额字符串契约。
