## 4. 实施结果

### 4.1 项目成员

- `PmProjectMemberController` 的 POST/PUT 仅接收 `CreateProjectMemberRequest` / `UpdateProjectMemberRequest`。
- Create 从 request、path 与 `UserContext` 显式构造内部实体；Update 先加载现有实体，再逐字段更新业务白名单。
- Update 不可换 `userId`；Create 只接受当前租户内 `ENABLE` 用户；租户、项目、用户、角色与软删除恢复不变量保持。
- `PmProjectMember` 只继承 `BaseEntity.createdAt/updatedAt`，不再声明 `createdTime/updatedTime` 或父类影子字段。
- 恢复保留原 `created_at/created_by`，由服务器刷新 `updated_at/updated_by`；测试记录 create→update→restore 各阶段审计值。

### 4.2 合同变更与同根实体

- 合同变更新增/更新改为独立 DTO + Service 白名单；`createdBy/At`、`updatedBy/At`、`deletedFlag` 均为服务端字段。
- `OrgCompany`、`OrgDepartment`、`OrgPosition`、`MatPurchaseRequest`、`MatPurchaseRequestItem`、`CostTarget`、`CostTargetItem`、`MatWarehouse` 补齐审计及实际可达的服务端字段 `READ_ONLY`。
- 采购申请创建清空客户端 id，更新保持租户/申请编号；明细批量保存清空批准数量与审批版本。
- 目标成本表头/明细创建清空客户端 id；明细归属由路径和 Service 决定。
- 仓库 id、租户、编码继续由服务端决定，状态入口统一验证。
- `MatRequisition`、`MatRequisitionItem`、`PayInvoice` 已有等价只读边界，只作为安全对照，未做样式性重写。
