## 失败分类与处置

- `tool_config`：Codemap 原按工作树原始字节哈希，同一 Git 内容因 CRLF/LF 物化不同被误判 stale；改用 Git 原生规范化对象 ID，自测与跨 worktree 复验通过。
- `environment_prerequisite`：隔离 worktree 先缺 Vite 依赖、backend 未绑定专用 demo 库、Compose 网络不同名，且原 demo 账号无该库权限；分别用 frozen lockfile、专用数据源、既有外部网络和既有精确授权账号恢复，未新增数据库权限。首次 Live 又因 Windows 端口连接池耗尽出现 `ERR_NO_BUFFER_SPACE`；等待 `TIME_WAIT` 恢复、确认进程残留 0 后重跑，未用超时/重试掩盖。
- `quality_or_security`：恢复后暴露告警 API 12 条而页面每页 10 条，旧测试错将单页 DOM 与全量记录直接对比；改为逐页验收并完整复跑 80/80。
- `quality_or_security`：独立复核发现质量子号耗尽文案误写“当日”，与同检查单作用域不符；改为“该检查单问题编号已达到999条”并新增 message 断言 1/1。因运行时代码变化，又在新 SHA 完整复跑 Live 80/80。
- `tool_invocation`：GitHub 保护首次回读的 PowerShell 命令未引用 `{owner}/{repo}` 占位符，未发起有效 API 请求；改用显式仓库路径后读取成功，无外部写入。文案专项测试首次外层 120 秒超时，调整调用超时后原命令 1/1 通过。
