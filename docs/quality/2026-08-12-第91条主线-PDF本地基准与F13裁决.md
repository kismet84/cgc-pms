# 第91条主线 PDF 本地基准与 F13 裁决

> 日期：2026-08-12
> 范围：`M91-F13`，仅本地 renderer 基准
> 环境：本地 Windows 11 / Eclipse Adoptium Java `21.0.11+10-LTS`；不涉及非本地环境、生产数据库或生产发布
> 裁决：`CLOSED / INSUFFICIENT_SIGNED_THRESHOLDS / NO_ASYNC_IMPLEMENTATION`

## 1. 测量边界

- 被测对象：`OpenHtmlToPdfDocumentRenderer.render`，版本 `openhtmltopdf 1.1.40 / pdfbox 3.0.8 / noto-sans-sc 6.1.0`。
- 不包含：HTTP、Controller、模板查询、Provider 数据组装、文件持久化、数据库或对象存储。因此本报告的 p50/p95 不能冒充端到端请求时延。
- 设备：16 个逻辑处理器，物理内存 `34,141,691,904` bytes，JVM 最大堆 `2,147,483,648` bytes。
- 固定 JVM 参数：`-Xms512m -Xmx2048m -XX:+UseG1GC -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Shanghai`；测试启动时读取并校验实际 fork 参数，不满足即拒绝产出基准。
- renderer 配置：并发 `2`、队列 `2`、单次超时 `15s`、PDF 上限 `20MiB`、页数上限 `100`。
- 每个场景先预热 5 次，再串行采样 30 次；渲染期间以 5ms 周期采样进程堆，记录场景基线、峰值和差值。堆采样是进程级近似值，不等于单请求精确分配量。
- 输入均包含内联 data PNG、A4 表格、中文和重复明细；场景分别为 20、120、200 行。

## 2. 可重复入口

普通 CI 默认跳过该基准；仅显式 opt-in 执行：

```powershell
$env:TEST_JWT_SECRET='<test-only-secret-at-least-64-bytes>'
$env:JDK_JAVA_OPTIONS='-Xms512m -Xmx2048m -XX:+UseG1GC -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Shanghai'
.\mvnw.cmd '-Dtest=DocumentGenerationLocalBenchmarkTest' '-Dcgc.m91.pdfBenchmark=true' test
```

测试文件：`backend/src/test/java/com/cgcpms/document/DocumentGenerationLocalBenchmarkTest.java`。统计行先于成功断言输出；即使正式样本失败，也会保留成功数、失败数、失败率、最大失败耗时和异常类型，避免失败证据被断言截断。

## 4. F13 裁决

第91条计划要求异步 PDF 进入实施前，由业务/技术共同签认请求时限、堆预算和失败率阈值。当前计划、质量载体和项目上下文中均不存在这些阈值。现有结果只能证明本地 renderer 在上述固定样本和硬界下可重复成功，不能证明端到端请求达到或超过未定义阈值。

因此：

- `M91-F13` 以“证据不足”正式关闭；不进入异步设计或实现。
- 保留现有同步生成、既有 generation fact/status/idempotency 和 bounded renderer executor。
- 不新增消息队列、任务状态框架、第二队列或 Backlog/计划项。
- 若以后出现已签认阈值，必须重新建立同环境的端到端 preview/generate 基准；只有可重复超阈值才重开，不复用本报告的 renderer-only p95 直接裁决。
