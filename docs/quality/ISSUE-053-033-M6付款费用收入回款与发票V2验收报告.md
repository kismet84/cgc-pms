- 五条路由逐项目消费服务端事实；台账达到`LEGACY_ONLY=29 / V2_ACCEPTED=58 / V2_SOURCE_AVAILABLE=0`。

- ID与金额保持稳定字符串；前端不计算可付、可收、核销、税额、累计金额或权威状态。
- 未新增数据库migration、平行资金账、应收应付模型、通用财务框架或依赖；未切正式入口、退役Legacy、commit、push、PR或发布生产。

## 2. 服务端权威、权限与并发

- 付款来源、额度、合同已付金额、付款申请状态、资金日记账写回和冲销互链均由服务端锁定事实裁决；外部交易号重复返回同一事实或稳定冲突。
- 业主结算按合同加行锁后重新汇总；并发创建不能突破合同当前金额。收入、应收、销项发票和回款使用稳定DTO，不向V2暴露原始`Map<String,Object>`。
- 发票列表后端消费`projectId`并与可访问项目集合求交；不可访问项目失败关闭为空页。新建发票只选择服务端成功付款记录，不手输付款记录主键。
- 发票更新、删除、校验和分配先锁业务对象；校验只接受当前发票对象下文档类型正确且病毒扫描为`CLEAN`的附件。
- 查询与动作权限分离；租户、项目、合同、付款申请、付款记录、收入及发票对象范围均由服务端复核。

## 5. 失败分类与关闭

- `quality_or_security`：发票页传`projectId`但后端未消费；在共享发票查询入口加入可访问项目交集并补控制器回归。
- `quality_or_security`：同页项目/路由快速切换时旧请求取消异常读取了新控制器状态，导致成功的费用请求被显示为失败；将Abort状态绑定到每次请求并复验。
- `test_or_fixture`：发票和付款闭环测试附件缺少`CLEAN`扫描事实、收入真实提交缺少受控审批实例；修正专属夹具后联合专项通过。
- `environment_prerequisite`：Docker Vite保留旧转换缓存；重启V2 dev容器并以当前源码复验。
