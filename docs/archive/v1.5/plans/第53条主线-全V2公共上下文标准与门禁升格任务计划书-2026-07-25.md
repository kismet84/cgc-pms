# 第53条主线 全 V2 公共上下文标准与门禁升格任务计划书

**Goal:** 将 M4 已验证的公共项目与报告期交互合同升格为所有当前及后续 Clean-room V2 路由的强制标准和自动退出门，修复 M5 页面把“全部项目”误判为缺少上下文的问题。 **Architecture:** 继续复用唯一 `AppShell`、workspace store、导航目录和既有业务查询；以公共壳浏览器门禁验证状态转换与跨路由保留，以全页面静态门禁禁止项目空态死门，并复用各业务域真实 DTO E2E 验证聚合结果。不建立第二套路由清单、页面能力白名单或新组件。项目列表读取必须支持授权范围聚合，写动作仍要求具体项目；报告期保持 URL 与跨导航上下文，具有时间维度的页面继续由专项 E2E 证明服务端日期边界。

## 1. 范围与非目标

范围：

- 校准 `docs/ui-v2/m1-design-system-baseline.md`，明确全 V2 可执行门禁。
- 修复供应商招采和采购执行把空 `projectId` 解释为不可用页面的行为。
- 新增公共上下文 Playwright 门禁和全页面静态门禁。
- 补齐全 V2 标题层级、动态分页、实现语言门禁，以及供应链页面的详情、密集记录、复合表头和状态门禁。
- 保留 M4 预算、产值、日报等时间维度页面已有的服务端日期边界专项断言。

非目标：

- 不隐藏、禁用或复制公共壳项目/报告期控件。
- 不新增路由能力元数据、第二套上下文 store 或页面私有筛选器。
- 不改变写操作必须绑定具体项目、后端权限、租户范围、状态机、数据库或 Legacy UI。

## 2. 验收标准

1. 唯一公共壳完成具体项目、全部项目、具体报告期和全部报告期状态转换；全部导航目录 V2 路由自动纳入可用性检查。
2. 切回“全部项目”后 URL 不携带 `projectId`，页面不得显示“请选择项目”或“请先选择项目”。
3. 选择具体报告期后 URL 携带 `period=YYYY-MM`，跨路由保留；切回全部报告期后参数删除。
4. 供应商招采在全部项目下聚合当前用户可见项目的只读事实；采购列表不带 `projectId` 请求授权聚合事实。
5. 新增页面自动进入静态门禁，无需维护第二份路由清单。
6. 目标单测、全 V2 类型检查、Lint、构建、公共上下文 E2E 和差异检查通过。
7. 供应链 8 个可见页面保持单 H1、21px 标题、中文状态、无页面级横向溢出；密集记录用表格，详情使用标准弹窗。

## 3. 风险与回滚

| 风险 | 控制 | 回滚 |
| --- | --- | --- |
| 聚合读取放大供应商请求数 | 只对公共 store 已返回的可见项目并发读取；写动作继续要求具体项目 | 回退供应商页面聚合读取 |
| 通用 E2E 被业务接口差异干扰 | 门禁只裁决公共壳、URL 和项目空态；业务语义由各页面专项 E2E 负责 | 回退新增 E2E |
| 既有脏工作区重叠 | 只对目标文件增量 patch，不覆盖 M5 现有实现 | 按本任务文件级 diff 精确回退 |
