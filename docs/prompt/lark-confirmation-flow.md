# 飞书通知与确认交互流程

仅在必须由用户决策且用户已要求通过飞书确认时使用。可自行判断并继续的问题不触发确认。

## 目标与授权

- 收件用户或会话 ID 由当前调用方显式提供或从已验证会话上下文取得；仓库不保存固定个人/群聊 ID。
- 发消息、拉取回复按当前 `lark-cli` 命令 schema 和认证状态执行，不把示例参数当作真实目标。
- 外部写操作只有在既有明确授权覆盖，或收到与本次确认绑定的有效回复后才继续。

## 确认消息模板

```text
【执行确认】Phase X - <简短标题>
问题：<描述>
选项：
A) <选项A>
B) <选项B>
C) <选项C>
请回复 A/B/C；超时将停止该决策点并保持现状。
```

## 执行步骤

1. 发送确认请求，记录目标、问题、选项和消息标识。
2. 暂停依赖该决策的工作；等待后读取同一会话的新回复。
3. 仅接受本次请求之后的有效 A/B/C 回复，并绑定发送者与消息标识。
4. 无回复、回复无效或身份/会话不匹配时，可再做一次有界读取；仍无有效回复则停止该决策点并报告阻塞。

## 禁止事项

- 不因超时自动选择任何会产生写入、授权扩大、Git、生产或外部消息的选项。
- 不读取仓库硬编码的个人、群聊或租户标识。
- 不在等待期间执行依赖该选择的工作，不进入无限轮询或自愈循环。
